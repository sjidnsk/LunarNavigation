# 导航终端问题的本质原因与协议边界

2026-10-29。用户要求停止逐症状推进，先解释共同原因。本报告基于当前源码与r5至r9真实隔离证据，不以一次通过宣称架构充分，不提出参数试调。

## 核心结论

任务目标、执行机动、滚动参考和控制器几何子阶段没有完全独立的身份及生命周期。标准Path本来只是一次局部几何快照，却被多处用来推断阶段替换权限、终点语义、是否必须停车，以及停滞比较对象。参考窗口每20Hz变化，任务目标与执行机动不应跟着重启；物理阶段真的改变时，进展比较域又必须显式改变。这两类事件缺少统一定义，构成此前几种故障的共同原因。

现有能力模型已允许差速车辆边走边转、原地旋转，仍保留独立v/w及加速度、安全停车与碰撞认证。当前证据首先指向离散执行语义与反馈链，不足以认定MPCC/MPPI优化代价必然把停车当成唯一最优。

## 源码中的结构证据

- `lunar_planning_msgs/msg/PathExecutionReference.msg`提供session、reference_revision、intent和阈值，尚无稳定机动身份。session是任务、intent是种类、revision是快照；同任务FOLLOW→BRAKE→FINAL_ALIGN→BRAKE→FINAL_ALIGN时，session+intent不能区分两次旋转。
- `standard_path_follower.py:_alignment_extension`必须靠中心、方向、累计角和旧窗口覆盖反推续接。保守拒绝有安全价值，但“必须覆盖历史horizon尾点”仍把旧快照升级成执行承诺；未来需要显式区分真正反向屏障、同向采样和时域尾点。
- `mppi.py`的`_last_pose=(anchor,travel,best_angle)`没有进展域和机动标签；`_accept_pending`、停车切换、子阶段完成及显式退休分别维护锚。最近修复补上了缺失交接，尚未把生命周期集中到统一事件。
- 停滞计时在Mppi.update分支累计，_stop分支不累计。目标总期限、机动停滞期限、停车期限、传输反馈期限应分别有对象和转换规则，不能隐式依赖执行走了哪个函数。
- 当前COMPLETED/WAITING既可能表示本局部几何结束，也可能表示已停车；任务层再用真实目标条件防止误报。安全门禁已加强，但两层完成对象仍需明确命名。

## 职责边界与建议的最小统一模型

全局规划负责可通行路线；局部规划负责当前能力/地图约束下的运动参考及明确机动语义；跟踪器执行、认证、报告真实状态；任务协调器拥有不可变最终目标和最终完成权限。DRL只在导航结果和新鲜观测反馈后决定下一个目标。跟踪器不应从局部窗口末点猜任务终点，也不应通过改写规划几何替规划器弥补意图不一致。

建议先统一三层身份，再统一事件，不重写三个算法：

|对象|身份与不变量|
|导航任务|session_id绑定不可变最终位姿；换目标产生新session|
|执行机动|稳定maneuver_id或等价阶段序号，绑定目标、进展域、方向、替换/退休权限和完成条件；同机动刷新不变|
|局部参考|reference_revision+digest属于一个maneuver，仅表示本次几何/地图快照，不触发机动重启|

控制器反馈分别表达“哪个机动正在执行”“哪个参考实际应用”“几何窗口耗尽/真实屏障完成/认证停稳/机动完成/故障”。不能只让一个COMPLETED或segment_revision承担所有含义。临时BRAKE是同机动暂停还是退休旧机动，必须由owner显式指定，不能仅靠BRAKE字符串猜测。

进展协议应按域定义。平移比较同机动内真实有向位移；旋转比较连续lift后的真实有向角进展。参考发布、接受、重绑、命令输出和重复观测都不算物理进展。阶段转换只改变比较基准，不凭空产生进展；静止刷新不能续命。安全停车、传输等待及故障各有独立有界恢复条件，故障只能由明确的新任务恢复协议解除。

验收先覆盖协议性质：相同实测运动在不同路径刷新频率/采样密度/消息乱序下，机动身份、进展和最终结果一致；合法窗口缩短不自动成为新目标；真正反向屏障不可跳；跨pi/多圈连续；静止无限刷新仍超时；故障不能被新参考洗掉。然后才评估末段时长、平滑性、优化成本与采样效率。

## 平滑接近目标：已有机制与待验证部分

不能认定“进入0.1m前完全没有最终yaw”。coordinator在not arrived_xy且已有路线时调用extract_reference(terminal_yaw=目标yaw)；reference.py在局部窗实际覆盖真实路线末点时保留terminal_yaw；local_mpcc.py的_approach_yaw按剩余路程平滑融合，非spin模式逐预测节点注入。已有末段软姿态目标。

其在线生效仍受局部窗口reaches_end和模式选择约束。需要记录terminal_yaw、reaches_end、select_mode及各预测节点desired_yaw，才能解释某条轨迹为何主要到点后再转；不能只凭运行观感修改混合距离、权重或阈值。全局路线、局部姿态参考、跟踪器执行许可必须使用同一机动定义来评估这一机制。
