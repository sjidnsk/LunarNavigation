# P4 地面补足与可通行性职责审查

日期：2026-09-23。范围：核查局部坡面拟合、补足后的评价与架构职责；不改 P3、不扩大运动能力、不修改碰撞包络、不以提高 FREE 数量作为正确性标准。

## 结论

P3 输入适配 → 原始高程快照 → P4 地形/整机派生 → 规划消费的主架构合理，P3/P4 边界没有被破坏。地图处理内部已经出现职责耦合：`EvaluateTerrainPatch` 同时负责估计缺测地面、计算可信度、背景拟合、局部高差和平台支持判断。应在现有 P4 core 内做小范围分离，不新增 ROS 节点、话题或并行地图系统。

当前确实是在拟合坡面并看去坡残差，而不是复制同一高度。上一轮“20 cm 区域高程跨度”统计不能用于证明拟合失败。本次直接跟踪实际拟合拒绝与后续拒绝位置。

## 实际诊断

使用同一份 320×320 / 5 cm P3 float32 输入，机器人参考位置附近 1 m、1257 个格子。参考位姿比高程晚约 2.2 s。本次只分析内在地形评价，不将其当作整机通行或实车闭环结果。

| 评价结果 | 格子数 |
|---|---:|
| 内在 FREE | 445 |
| 背景样本/分布不足 | 2 |
| 中心估计未成功 | 200 |
| 中心存在，但中央局部仍有无法评价的格子 | 359 |
| 完成地形计算，但高低表面支持不足 | 251 |

各次尝试邻域的诊断共 18571 次（不是独立格子）：样本数不足 6497、角度分布不足 857、平台坡度拒绝 3563、去坡后的区间端点残差拒绝 5405、分数低于阈值 36、接受 5604。坡度与残差拒绝可能同时发生，不能直接累加成格子数。

因此，当前 3 cm 判据已经是拟合后的残差；把原始高程平滑一下再重复当前处理，不能保证解决剩余 UNKNOWN。

## 已证实的职责问题

### 1. 观测估计提前依赖平台爬坡能力

补点阶段使用 `capability.maximum_slope_rad` 判断是否允许形成估计。本机最小探针使用完全一致的 0.45 rad（约 25.8°）平面：

- 密集观测：轮式 BLOCKED / 可信度 1，足式 FREE / 可信度 1。
- 每隔 20 cm 一个观测、5 cm 网格：轮式 UNKNOWN / 0，足式 FREE / 约 0.412。

坡面本身是可可靠估计的，但轮式“爬不上去”被提前转换成“观测未知”。地面估计应输出坡面与可信度，再由平台能力判 BLOCKED。仅在仓库外移除该提前坡度门限的反事实探针，使本帧附近内在 FREE 从 445 变为 452、UNKNOWN 从 812 变为 805；没有评估整机状态，也未作为生产修复。这证明此耦合存在，也证明只改这一处不足以解决真实帧问题。

### 2. 同一缺测格会随父窗口重复估计

当前内在格子评价有缓存，但每次评价内部又为中央邻格拟合。原始支持集合受到父窗口裁剪，估计不完全由“目标格子+原始快照”决定。

本次附近的中间估计记录中，667 个缺测格被至少两个父窗口估计；11 个格子的估计高程跨度超过 5 mm，其中 5 个超过 1 cm，最大约 20.1 mm。记录含最终未通过评价的父窗口，不能直接称为已发布地图的高度跳变。它仍证明估计缺少单一、可复用的定义，并增加重复计算。

### 3. 估计后的背景与支持判据仍依赖细网格排列

估计点附加到点集后，参与相邻梯度与再次背景拟合；真实高低表面支持则仍要求 5×5 范围内的真实点组成相邻格子对。两者分别承担趋势估计、真实地形约束，但合在一个函数中，且使用不同的证据集合。

足式局部残差跨度超过 12.5 mm，就进入高低表面支持检查，即使没有超过 0.5 m 台阶能力。251 个附近格子因此 UNKNOWN。此处不能直接删除真实高差约束；需要将连续粗糙坡面的拟合残差与明确的两层地形证据区分开。

诊断还计算了“改用精化平面去坡”的残差：251 个格子中有 139 个残差跨度下降，只有 8 个会降至 12.5 mm 以下。这只是残差指标变化，不是 FREE 恢复数量，说明单纯切换去坡平面不能解决全部问题。全局替换也可能把真实台阶拟合成坡面，未进入部署代码。

## 保留的合理边界

- `ElevationPipeline` 负责接收、快照版本和派生调度；P3 输入格式与数据不由地形评价修改。
- `PersistentElevationMap` 保存原始观测的高程区间；补足没有写回该区间。多次观测采用区间极值合并，不是统计高斯不确定度，本次单帧不足以评价长期融合质量。
- `FineCellEvaluator` 负责机身覆盖范围与障碍优先级，再计算可通行代价；尺寸与能力分别保留。
- 路径搜索与简化消费同一可通行性/代价，不执行补地形。
- 终点与足式支持查询仍检查原始高程是否存在。起点盲区假设有独立的请求级处理，不应纳入地面估计。
- 工程可信度与可通行状态分开保存，这个方向保留；高可信也可以是明确障碍。

## 最小调整方案（本轮未实施行为重构）

在现有 core 内提取一个与平台能力无关的 `TerrainObservationEstimator` 内部帮助类或函数，输出最小地面证据：地面趋势/估计高程、真实观测相对趋势的残差、连续可信度及是否包含推断。估计不接收车体尺寸、台阶能力、最大坡度或规划权重。

每个原始快照内，每个目标格使用确定的物理邻域独立计算并缓存；轮式和足式复用相同观测算法。原始观测保留作障碍/高差约束，推断不递归参与新的观测支持计数。连续坡面允许高度平滑变化；真实断层两侧分别评价，不用平滑去抹掉原始证据。

随后由平台评价读取地形特征并应用坡度、台阶、底盘净空、支持等限制；再由整机评价应用真实包络并汇总可信度与代价。继续维持现有 UNKNOWN / FREE / BLOCKED 和一个连续可信度，不增加多套外部状态。

缓存抽离后必须重新核对增量依赖范围：独立估计邻域与地形评价邻域叠加，再加整机半径和净空范围。不能原样复用旧的单一背景窗口失效范围，否则可能漏更新。缓存键必须绑定原始快照/版本和观测参数，不能跨原始版本或平台评价参数混用结果。

验收应覆盖：同一原始格在不同查询顺序/父格下得到相同估计；不同平台得到一致的地面证据但允许通行结论不同；平滑坡面、稀疏噪声地面、单侧/共线、真实台阶/沟边、原始障碍保留；分数与全量/增量结果一致；同帧整机可通行性、规划可达性及处理开销。先验证这一小范围结构调整，再根据真实证据讨论残差/支持策略，不继续逐项放宽阈值凑 FREE。
