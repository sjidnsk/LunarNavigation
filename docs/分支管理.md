# 分支管理

本规范落实 2026-10-16 用户指定结构。主线的目标是完整项目架构；当前包含哪些模块、某模块是否
已成熟，须以实际代码和该次验收为准，不能把分支目标写成所有模块已完成的声明。

## 六条长期线

|分支|职责|接收与输出|
|---|---|---|
|`integration/pure-planner-orin`|完整架构与通过适用验证的成熟模块算法|接收通用修复和成熟模块晋级；向开发线、相关应用线同步|
|`app/orin-unreal-simulation`|Orin 与外部 TCP 仿真协议、输入和部署适配|接收主线公共能力；验证 TCP 端到端边界|
|`app/orin-real-vehicle`|轮式实车 Orin 输入、能力和部署适配|接收主线公共能力；单独进行轮式设备验收|
|`app/orin-legged-vehicle`|足式实车 Orin 输入、能力和部署适配|接收主线公共能力；单独进行足式设备验收|
|`dev/terrain-confidence`|地形观测、通行性置信度及比较实验开发集成|接收所属专题；成熟模块晋级主线|
|`dev/drl-exploration`|DRL 探索模块唯一活动开发集成线|接收所属专题；成熟代码模块晋级主线|

专题分支不是长期分叉。`specialty → owner dev → integration → app` 是模块开发流向；主线所属
公共专题则 `specialty → integration → dev/app`。应用专用专题先回对应 app，其中可复用部分单独
提炼回主线，避免把设备配置带入所有平台。同步可以兼容合并或按目标接口明确适配；必须保留来源
SHA、目标提交、行为证据与差异说明，禁止靠分支名或 patch-id 宣称等价适配已经验收。

## 模块归属与晋级

|模块/改动|初始 owner|晋级门槛|
|---|---|---|
|公共地图接口、导航、全局/局部规划、控制及纯探索公共能力|主线|受影响契约与离线测试；有运行接口变化时另做对应环境构建/测试|
|地形拟合、观测统计、来源无关通行地图、置信度实验|`dev/terrain-confidence`|数据语义、冻结输入对比、地图/规划兼容性证据|
|DRL 状态/动作、目标选择、回放、训练和评估代码|`dev/drl-exploration`|边界明确、功能实现、相关测试、接口/资源预算和依赖审查|
|TCP 协议与 Unreal 输入/部署|`app/orin-unreal-simulation`|协议离线测试及目标 TCP 环境单独验收|
|轮式/足式部署、实车参数与传感器输入|对应 app|平台配置契约及对应 Humble/Orin/设备验收|

DRL 代码模块、学习中的模型权重、策略效果和应用部署是不同验收对象。训练尚未收敛可以限制策略
部署和效果声明，不自动阻止实现完整、通过适用验证的代码模块进入主线。模型、回放、日志和运行
环境属于受保护的仓库外资产。公共修复同步不得以修复为名整线上送尚未完成的训练实现；成熟模块
应按正常晋级进行。主线不应被永久限定为仅有公共导航。

## 提交与验收流程

1. 读任务、适用 AGENTS 和 owner 规则，核验预期分支、工作树与 dirty 状态；在独立专题树实现。
2. 审阅未提交来源，记录原 SHA、文件哈希和适用性。只纳入当前专题文件，显式路径 `git add`。
3. 执行适用契约、离线测试和语法/只读 CLI 检查；实际环境未运行须标 `NOT_RUN`。
4. 提交后由独立审查核对 base/head、范围、测试、风险；再由负责整合者合回 owner。
5. 成熟模块晋级与同步逐目标更新台账：已合入、已等价适配、已替代历史、待完成或已提交待验收。
   每条结论注明范围和证据。一次盘点/备份不是整合完成；谱系和补丁等价不是功能验收。

不得 reset/rebase/amend、覆盖他人修改、删除原分支/工作树、推送、修改 origin、创建 PR、启动或
重启训练/仿真/车辆服务。保留 [AGENTS](../AGENTS.md) 的全部安全和验证规则。
Jazzy、Humble、Orin、DDS、rosbag、RViz 和实车证据分别记录，低层测试不能外推设备就绪。
当前公共离线工具及使用边界见 [导航诊断工具](../scripts/navigation/README.md)。
