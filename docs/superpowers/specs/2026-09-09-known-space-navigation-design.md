# 已知空间观测位姿导航

日期：2026-09-09。用户已批准的重构；取代导航内部自主前沿和方向性出口回退。

## 动作与职责

探索策略输出连续 `(x,y,yaw)` 观测位姿。落脚位置必须属于当前 fine 快照的已知 FREE 格，
可达性由平台规划器认证；未知区域是观测对象。目标未知、阻塞、不可达时不得吸附或替换为另一目标。
允许经过已知区域和任务范围外绕行。覆盖率、奖励、探索终止仍完全属于探索层。

导航流程为：目标已知性检查 → 有界起点盲区补丁 → 完整已知空间路线 → 首个局部窗口前缀 →
局部平台路径 → 控制执行确认。完成非最终段后从最新快照重新求同一最终目标的路线。
未知/阻塞目标返回 INVALID_GOAL / GOAL_NOT_KNOWN_FREE 或 GOAL_BLOCKED；无连通路线返回
NO_PATH / NO_KNOWN_SPACE_ROUTE。失败结束当前导航动作，不等于探索任务完成或目标永久不可达。

## 单一平台搜索规则

`KnownSpaceRoutePlanner` 复用 `WheelLocalPlanner` / `LeggedLocalPlanner` 原有搜索核：
轮式保留8邻域、禁止切角、起点phase和终点朝向规则；腿式保留支撑、台阶、间隙、动作跨度、
有向边与终点朝向认证。全程搜索使用稀疏记录，局部搜索保持原有稠密缓冲和64m窗口。
起点补丁只由既有模块在局部窗口建立；扩大路线视图不扩大假设区域，退出补丁后不能重新进入假设格。

`KnownSpaceRoute` 与 coarse `GlobalRoute` 使用不同类型。前者来自同一 fine revision 的平台路径，
后者仍可供原有独立粗规划分析使用，但不能再传给导航的路线分段接口。
完整路线保留原始认证节点；执行段仍由本平台局部规划器生成。全程搜索没有起终点矩形裁剪，
因此允许绕障时远离目标。未新增端点黑名单、循环计数器或覆盖率看门狗。

## 路线分段

`LocalTargetSelector` 的职责已收缩为前缀提取：校验快照、起终点和目标已知性，沿已认证路线
扫描至首次出窗，选最后一个已知normal节点。即使路线后续重新进入窗口，也不能跳到重入点。
整条路线都在窗口内才选择最终目标及终点yaw。无前缀则明确失败，不另扫空闲格或前沿。

固定地图上，每次前缀执行消耗正代价路线；不以欧氏距离单调下降为要求，也不禁止合理回访。
地图变化仍由已有路径失效和重规划链处理。控制器只执行当前有效reference，保持0.2m/s、
前进/后退转弯及原地旋转能力。

## 诊断、预算与兼容

EXECUTING等未执行路线搜索的周期标记global_guidance_status=NOT_RUN，避免默认UNAVAILABLE
被误读为上一次搜索失败。全程路线仍受现有global_subdeadline约束，超时是TIMEOUT，不能当成
已证明不可达。腿式索引仍受 UINT32_MAX / 4 个矩形格限制，容量不足报告
ROUTE_CAPACITY_EXCEEDED / INTERNAL_ERROR；本次1km任务不触及该上限。
稀疏记录消除了稠密矩形分配，并不意味着任意尺度的搜索时间或内存无限。

policy.goal_domain=known_free_observation_pose_v1 进入现有配置指纹；旧导航语义的检查点/经验
不能直接续训。正常失败动作仍保留原始动作、实际运动与新增观测，返回一条普通训练转移。
