## 已核对事实

1. P4 的 launch_settings 固定 exploration_strategy=none；组合 launch 已支持 frontier/drl，常规策略已有 incremental_exploration_node 和 NavigateToPose 客户端，无需新建策略或导航适配层。

## 选定方向与职责

推荐仅修接线及生命周期；不替换前沿算法，不重写导航，不新增 ROS 消息、任务身份、超时或进展累计器。替换整个探索实现不能解决已定位的接线及等待分类错误，还会扩大风险。

链路：P3 高程地图 → 现有独立探索地图/20 cm 栅格 → 前沿与观察点排序 → 当前 NavigateToPose Action → 全局几何路线 → 局部 MPCC → 连续 cmd_vel → P3 实测反馈 → Action 到达/等待/真实故障 → 探索下一决策。

- 探索负责区域、覆盖、前沿、观察朝向、目标选择与任务组织。
- 导航负责路线、局部运动、定位中断停车及恢复重规划、到达判定。
- TCP 入口负责选择并启动已有组件、转发输入与速度接口；不解释规划模式或重新判定到达。
- 暂不可用与真实执行故障分开。真实故障仍可暂停并显示原因，保留区域任务，由人恢复或结束；不得伪装成地点不可达。
