# 新导航与标准 Path 跟踪器集成设计

任务沿用 NAV-1CM-20261026，关联 FOLLOWER-SWEPT-MAP-20261024；owner 为 integration/pure-planner-orin。
用户2026-10-28授权：保存两个专题提交 → 汇合两地主线 → 集成回归 → 标准Path及地图接入 → 短联合验证后切轮式默认入口。

## 已固定的接口和边界

- 新规划器输入 P3 GridMap elevation、Odometry、最新 TF 和 PoseStamped(x,y,yaw)，业务输出仍只有两条 nav_msgs/Path。
- 跟踪器接受标准Path并自行重定时，不要求上游增加PathReference、Action、ACK或地图服务。
- 局部地图固定0.01m、500×500、5m×5m；源分辨率任意有效正值，支持运行中变化、滚动与旋转。重采样不增加观测精度。
- 全局允许UNKNOWN；局部allow_unknown可配置，默认false。未知来源保持未知；暂不补起步盲区。
- 默认轮式车体1.182×0.818m，|v|≤0.2m/s、|w|≤1.0rad/s、线/角加速度0.5、行进曲率1.0；能力文件→显式参数覆盖，跟踪器不得采用比声明能力更宽的限制。
- 最终xy/yaw容差0.1m/0.05rad，停稳|v|、|w|≤0.01，保持至少0.3s作为联合验证证据。
- 不因单次计算超过50ms而清空仍有效的参考；地图/轨迹几何与真实制动条件仍独立检查。
- 最新有效目标替换；无效新目标保留原目标；新目标无路仍保留，不自动回退；旧目标迟到结果隔离。
- 旧MPPI/PathReference入口及现役冻结训练评测保持；只切换轮式新入口，不启动真实车辆或改变足式默认。

## 实现选择

在controller侧为mppi_path_follower增加标准Path模式，保留有序(x,y,body_yaw)及重复xy转向段；不把每帧stamp当新会话。兼容滚动更新按实测状态投影，保留实际指令历史和停滞时间，禁止每帧重置制动。局部段耗尽进入等待，不向外宣称导航任务完成。空Path、坏Path和停发产生受限制动意图；制动期间保留命令历史。

地图采用薄P3适配，复用nav1cm中的源几何、P3MapStore、NativeTerrain等纯地图能力；不导入planner session/coordinator/node。由独立地图worker交接不可变快照，接收活性与几何版本分开。将intrinsic地图转换为包含完整车体支持的中心可行图（首版允许保守外接圆），未知策略显式控制，不可直接把未膨胀数组送入原GridMap。旧GetPolicyMap来源保留显式可选。

标准模式使用reliable/volatile Path订阅，支持最新TF链、/tf_static和零stamp。保留必要数值/结构检查，不新增严格stamp同步、协方差或可选元数据门槛。

备选方案为让新规划器输出旧PathReference并提供地图服务，会扩大已确认接口；或继续启动旧导航获取地图，会重复导航职责，因此本轮不采用。上述薄适配方式为实施判断，遵循用户已确认接口与执行顺序，不新增一轮审批。

## 验证与切换

先保存并合并两套已验证模块，在Humble独立目录构建/回归；然后按TDD补标准Path、P3地图/TF和真实三进程链路。联合验证使用真实planner、真实follower、独立命令积分/矩形碰撞核验，6–12m合成地图与短距离运动；不以旧consumer代替follower。覆盖前进/倒车/转向、滚动参考、障碍/地图更新、空/停发Path及计算延迟；统一记录生产SHA、正式全局结果、约束、真实状态、进程退出。

联合验证通过并独立审查后再切轮式代码默认入口，保留显式旧入口。应用专用脚本在app/orin-real-vehicle所属专题适配；主线/应用工作树有其他修改时保持原样，使用独立集成树或清洁远端落地，不擅自stash或重置。代码默认变更不代表Orin/实车验收。
