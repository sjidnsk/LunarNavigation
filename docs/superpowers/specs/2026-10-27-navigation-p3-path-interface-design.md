# 轮式新规划器：P3 输入与标准 Path 输出约定

日期：2026-10-27。任务：NAV-1CM-20261026。

状态：用户于2026-10-27整体确认；Task1–4及r5b/r6生产修复均已通过规格与质量双审，监督P2经独立窄规格及原QA复审关闭，整体独立复审PASS。本阶段实现、验证与复审于2026-10-28完成，暂停保留源码待用户审阅及后续提交/合入授权；边界见[实施报告](../../reports/2026-10-27-nav1cm-p3-interface-validation.md)。

## 1. 范围

- 轮式平台；复用已有高程累计、地形判定和轮式能力配置。
- 接收 P3 原生地图分辨率，不要求输入等于某个预设值；分辨率变化时自动适配地图表示和派生缓存，保留当前目标。
- 局部计算始终为 1 cm、5 m × 5 m、500 × 500 格，车体中心前后左右各 2.5 m。源地图转换为厘米计算网格不会增加真实观测精度。
- 全局使用米制几何参考，不要求将整个大范围地图密化为 1 cm 栅格。
- 保留 UNKNOWN。全局允许经过未知，局部是否允许未知可配置。本轮暂不补起步盲区。
- 对外提供四类输入和两条路径；实际车辆控制由下游负责。

## 2. 输入与输出

下列目标话题名、目标消息类型和 TF 默认来源是本稿提出的默认值，一并交用户确认。话题均可通过参数或 ROS remap 调整。

| 方向 | 话题 | ROS 类型 | 约定 |
| --- | --- | --- | --- |
| 输入：地图 | `/Car/T3/mapping/grid_map` | `grid_map_msgs/msg/GridMap` | 使用 `elevation` 及消息实际分辨率、原点和布局；复用已有地图处理能力。 |
| 输入：状态 | `/Car/T3/localization/odometry` | `nav_msgs/msg/Odometry` | 获取位置、朝向和车体速度 `v,w`。 |
| 输入：TF | 默认 `/tf`、`/tf_static` | `tf2_msgs/msg/TFMessage` | 使用可取得的最新变换统一坐标；也可配置使用既有 `/P4/input/map_to_odom`。 |
| 输入：目标 | `/Car/T4/navigation/goal` | `geometry_msgs/msg/PoseStamped` | 目标平面位置及最终车体朝向 `(x,y,yaw)`。 |
| 输出：全局路线 | `/Car/T4/planning/global_route` | `nav_msgs/msg/Path` | 当前目标的全局几何参考，用于观察整体绕行。 |
| 输出：局部路径 | `/Car/T4/planning/local_path` | `nav_msgs/msg/Path` | 当前局部窗口内优化后的路径，供下游跟踪。 |

目标坐标系默认 `map`；`frame_id` 留空也按 `map` 处理，其他坐标系在有相应 TF 时转换。两条输出路径统一使用 `map`。首版以平面位置和 yaw 为规划量。

## 3. 目标行为

- 新目标先校验，最新有效目标替换当前目标；无效新目标提示原因，保留当前目标。
- 目标位姿与已知障碍冲突时判为无效；未知、地图外不因未观测而拒收。
- 目标有效不要求已经找到路线；接受新目标后，即使暂时无路也保留新目标并周期重规划，不自动回到旧目标。
- 目标更换后，旧目标的迟到规划结果不再发布；切换期间不把旧目标路径当成新目标的路径。
- 最终位置和朝向均为终端条件。建议默认位置容差 `0.1 m`、朝向容差 `0.05 rad`；到达同时要求停稳，阈值作为参数沿用轮式验证设置。
- 允许原地转向，检查整个车体旋转过程；中途局部段不强制采用最终目标朝向。
- 目标接受后若因地图更新暂时受阻，保留目标、等待重新可规划，不恢复历史目标。

## 4. 路径内容与时间

- 全局路径只表达几何参考，`Path.header.stamp` 为生成时间，不承诺各点的执行时刻。
- 局部路径各点包含位置和实际车体朝向。保留倒车、原地转向等段的位姿顺序，不按位置相同而删除转向点。
- 局部 `Path.header.stamp` 为参考起始时刻 `t0`；各点 `PoseStamped.header.stamp` 为预计经过时刻 `t0 + ti`，使用 ROS 时间基准。
- 预计经过时间是本项目对标准消息字段的约定。下游可按参考时序跟踪，也可使用几何路径自行安排速度和经过时间。
- 下游自行重定时后负责满足其速度、转向、加速度和制动约束，不能直接沿用原计划时序的认证；不为此增加自定义路径消息或认证回传协议。

## 5. 更新、等待与空路径

- 全局、局部按各自周期更新，避免相互阻塞；计算频率与发布频率作为运行参数，不成为 P3 输入的准入条件。
- 同一目标计算尚未完成或单次超过 50 ms 时，仍可继续提供当前状态和地图下有效的旧局部路径，不仅因耗时波动而清空路径。
- 没有可执行局部路径时发布空 `local_path`，表示下游应受控停车；当前目标继续保留，恢复有效路径后继续导航。
- 停车处理应保留反应和制动余量，不把等到路径完全耗尽才开始停车作为策略。
- 当前目标没有可用全局参考时输出空 `global_route`；两条路径都不能沿用其他目标的结果。
- 规划节点停止发布时，下游通过路径新鲜度检查受控停车；空路径不代表目标已完成或被取消。
- 目标拒绝和等待原因先通过日志说明，本稿不强制增加状态话题、Action 或地图服务。

## 6. 输入兼容原则

- TF 时间戳缺省、为零或静态 TF 不作为拒收理由；不额外要求地图、里程计、TF 的时间戳严格同步。
- 不以地图分辨率与配置不相等为错误；源分辨率与内部固定 1 cm 计算分辨率分开处理。
- 只保留无法计算时必需的数值和结构检查，例如非正分辨率、尺寸与数据不对应。高程 NaN 按 UNKNOWN 处理，不因此拒收整张地图。
- 必需计算数据尚未到达时等待并提示，不要求上游为接入额外补齐可选元数据。
