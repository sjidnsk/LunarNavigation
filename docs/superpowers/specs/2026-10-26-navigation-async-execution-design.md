# 轮式导航：异步规划、连续执行与隔离 Humble 验证

用户已授权按此前四步顺序推进。继续 NAV-1CM-20261026、原专题工作树；不提交、合并、推送、删除，不接 P3、起步盲区或实车。旧同步基准及证据保留。

## 1. 规划与执行解耦

新增 AsyncNavigationCoordinator，执行 tick 为20Hz，局部请求默认10Hz（可配置），全局仍1Hz。局部与全局均使用独立单worker进程，执行端仅非阻塞poll/submit。局部worker持有唯一MPCC实例和自身距离场缓存，至多一个在途任务；忙时保留最新世界/目标需求，不积压历史任务。冷构建/worker就绪与稳态分别记录。

执行端独占轨迹缓冲及逻辑执行时钟。请求/结果包含序号、世界epoch、路线version、目标身份、反馈/生成时间。迟到结果先按已流逝时间裁剪，再从当前反馈重积分剩余控制，独立认证当前窗口内的候选和实际动作；不能复制候选末态或沿用旧地图证书。反馈与预计接续偏差过大、来源陈旧、剩余时域不足时拒收并保留仍可用旧缓冲。容差属于离线验证配置，必须记录，不能宣称实车标定值。

每个执行动作按当前地图、初态、动力学、车体连续扫掠及制动尾段认证。剩余整段在接收/地图变化等需要时重新认证，不能因复用缓冲跳过当前动作校验。目标变障优先拒绝并制动。目标/路线/策略变更按版本处理，防止旧结果覆盖新状态。只有当前可执行轨迹不可用或安全条件不满足才采用受限认证制动，不以规划耗时50/100ms单独制动。轨迹耗尽不能无限外推最后控制。

局部窗口严格车体中心5m×5m、500²、1cm。未知策略可配置。轮式车体和限值与前轮一致，正式运动验证采用独立fast档.5m/s/.5rad/s、a/alpha=.5、行进曲率≤1，静止可自转。

旧同步coordinator保持兼容；新模块分别负责worker通信、缓冲裁剪/重积分及编排，不把ROS依赖引入算法核心。新tick尽量兼容CycleResult字段，新增统计通过事件或明确数据对象表达。

## 2. 峰值诊断

拆分MPCC reset、输入装填、solve调用、结果读取/校验的墙钟和进程CPU耗时，保留旧总计时的包含关系。记录每次尝试的状态、QP/SQP迭代和acados内部计时（仅使用本机固定版本实际支持的get_stats字段，不能编造）。不在未定位前删reset、改求解算法或放宽约束。

固定保存的136ms峰值对应输入做短重放，另测有限的正常与运动输入，保留全部样本。区分CPU计算、调度等待、重试和冷启动；没有复现就明确说未复现，不把假设当根因。

## 3. 延迟闭环

新增独立异步基准，模拟车辆在规划worker忙时仍每50ms执行并推进；控制时钟与求解完成时刻分开。先使用可注入runner验证100/150/250ms延迟、陈旧图/目标、换版、耗尽和不安全剩余段，再在真实Orin进程worker上做有界实际延迟测试。

场景沿用25m地图及短多弯/增障；不运行1km运动路线。记录请求/完成/接收/接入时间、反馈时间、缓冲余量、接续偏差、执行周期墙钟/CPU、超期和制动原因、真实动作及后态。延迟期间要有实际运动证据，不能以暂停模拟时钟等待结果冒充连续执行。若固定步离线模型没有覆盖执行器延迟或控制线程抖动，必须列明边界；另以墙钟节拍检查执行调度。

验收分开：非阻塞与版本安全、轨迹连续/约束及独立碰撞检查、复杂场景到达、性能分位与调度抖动。50ms仍仅统计，不将周期波动直接判为碰撞或规划无路。

## 4. 隔离 Humble 节点

新增独立ament_python验证包及启动/探针，仅使用隔离命名空间 `/nav1cm_verification/*` 和独立ROS_DOMAIN_ID。适配层只转换消息和调用核心；合成地图、反馈模型和探针属于验证工具。节点使用真实rclpy定时器、ROS消息与DDS，执行期间局部worker忙不能阻塞执行回调。

所有输入保持生成1cm地图，实际使用同一轮式限值。发布仅供验证的状态、轨迹和诊断；绝不发布生产车辆控制话题。Humble在P4_veri独立build/install/log目录构建、测试、启动后退出并收集节点/topic/时间戳证据。Windows静态、Orin原生、Humble节点/DDS及实车分层记录；ROS隔离验证不替代物理执行器证明。
