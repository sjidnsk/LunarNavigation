# VIPER 轮式工程适配

用户已确认：保留 VIPER 外观，按项目轮式基线重排轮组、碰撞并连接控制和传感器；激光雷达、双目相机和安装杆统一前置到车头。质量与标定先沿用旧仿真，总质量 50 kg、双目基线 0.14 m，标为待实机标定。

## 范围与架构

归属 `app/orin-unreal-simulation`，专题 `hk/isaac-viper-engineering-20261028`，基线 `2d9a8ce1620d951f110c36ab13e59d3bb478df16`。原模型、已交付展示场景和原地形保持只读。新建规范 4WS 物理骨架（9 刚体、8 关节），只引用固定版本 VIPER 的视觉叶，避免导入 447 kg 原生动力学。碰撞和惯性显式生成，初始速度及关节角归零。

采用此方案是因为：整车非均匀缩放会同时破坏轮径、轮宽、关节框架和惯性；直接保留 VIPER 的 17 关节也增加项目没有定义的主动机构。VIPER 的 mast、天线、钻具和材质作为视觉外观保留，项目执行机构仅包含四个转向和四个滚动关节。

## 冻结接口与数值

- 读取项目 `config/wheel_orin.yaml`，不复制另一份能力数字作为权威来源。
- 零转向名义包络 `1.182 × 0.818 × 1.29996 m`；轴距 `0.8175 m`，轮距 `0.67 m`，轮径 `0.319 m`，轮宽 `0.148 m`，底盘最低间隙 `0.21 m`。
- 基座 X 前、Y 左、Z 上，米/秒/弧度；转向 Z、滚动 Y；轮心 `(±0.40875, ±0.335, 0.1595)`。
- 质量来源为旧仿真：底盘 40 kg，四转向节各 0.5 kg，四轮各 2 kg；惯性按碰撞几何计算，50 kg 不是实车标定值。
- 零转向名义宽度不是转向扫掠宽度；极限连续扫掠约 1.0217 m，必须报告并验证，不篡改项目名义 footprint。轮拱/复合底盘避免全转向穿插。
- 速度、加速度、制动、曲率和自转限幅从能力文件加载。拒绝非有限值及非平面指令；命令超时 0.5 秒时停车。转向未到位时禁止滚动，模式切换先停车。
- 控制为 `geometry_msgs/Twist` `/Car/T5/Car_Cmd_Vel`；反馈 `/Car/T3/localization/odometry`、`/tf`、`/clock`。仿真真值里程计明确标为 truth adapter，不当作 SLAM 验收。
- 独立 `ROS_DOMAIN_ID=117`、`ROS_LOCALHOST_ONLY=1`，Kit 使用捆绑 Humble Python 3.12 ABI；主机 `/opt/ros/humble` 用于独立订阅/控制验收。不改变其他进程环境，不接入真实车辆域。
- 传感器前置，安装杆/外壳在车头包络内，实际光学/测距原点位于外壳前方，避免自身遮挡；相机 USD `-Z` 与 ROS optical `+Z` 显式转换。
- 双目基线 0.14 m，原相机焦距/孔径 24/48/36 mm，名义 HFOV 90°；初始 640×480、15 Hz。有效深度点云筛有限值、0.05–10 m，不把渲染裁剪范围冒充有效观测范围。
- 真 RTX LiDAR 使用 SDK 内置 schema 自建配置，不引用未缓存的在线 USD；原始回波与 10 m/90°有效点云分开发布。IMU 使用物理传感器，发布有效读数与仿真时间。频率和外参均标为仿真配置待标定。

## 验收

1. 纯 Python 验证前进、倒退、左右弧线、自转轮角/轮速、限幅、超时、异常命令及转向门控。
2. 实际 USD 验证规范拓扑、质量/惯性正定、全部关节目标、轮滚动全过程尺寸、名义包络/转向扫掠、复合碰撞和原始文件哈希。
3. 台式 Isaac 实际运行非零命令，测关节反馈、位移/转角、停车/超时；在主机 Humble 收到带一致仿真时间的 odom/TF/clock 和相机/深度/点云/IMU/LiDAR 数据。
4. 使用项目既有控制器做短距离跟踪验证，保存命令/反馈和失败证据，不以渲染或仅 topic 存在代替运动/数据验收。
5. 最后在台式打开工程场景及车头传感器视角，保存预览、配置一致性记录、使用命令和 NOT_RUN 边界。
