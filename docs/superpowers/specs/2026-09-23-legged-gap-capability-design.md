# 足式跨沟能力诊断与设计建议

状态：待评审方案；本轮仅诊断与文档，不实施跨沟功能。
基线：app/orin-legged-vehicle，dfa3d819d2e44145346959e729389d3757db9379。

## 目标与约束

目标是解释已有 maximum_gap_width_m=0.3 为什么没有完整跨沟效果，并给出可逐级验证的方案。
保留 5 cm 分辨率、普通行走的外接圆碰撞模型、UNKNOWN 不可通行语义；P3 源文件不修改。
保持低速 vx/omega 跟踪阶段，不引入横移、跳跃或实车动作发布；部署分支暂不合入主线。
机器人实际步态、足端可达域和跨沟 SDK 尚未接入，0.3 m 是配置上限，不能作为实测能力。

## 已有证据

[台阶与沟隙测试](../../validation/2026-09-23-legged-step-gap-benchmark.md)记录了
20 场景×3 分辨率×5 次共 300 次本机核心库运行。本轮读取原始结果与源码，不冒充重新运行。
5 cm 时：20–50 cm 单级上台阶和 40 cm 下台阶可规划，51 cm 高差拒绝；
5–35 cm NaN 缝均不可直穿；宽20 cm、深60 cm的已知坑也不可跨越；有侧路时绕行。
NaN 代表缺测，不能证明空沟。软件台阶路径也不能证明实际机器人能完成登阶。

## 方案比较

|方案|收益|限制/选择|
|---|---|---|
|放宽UNKNOWN或把沟改FREE|少量修改即可出现路径|不能区分缺测与空沟，破坏普通路径语义；不采用|
|独立跨沟候选与认证模块|保留现有普通规划，逐项暴露证据缺口，可先离线验证|推荐；需要新动作契约，候选不能直接下发|
|全足端、姿态与步态联合规划|能表达更完整的接触与动作约束|依赖真实机器人模型和控制能力，暂不作为第一阶段|

建议先实现第二种方案的离线候选诊断，后续由已验证的底盘动作库承担具体步态。
若底盘只有普通Twist且没有经过验证的自主跨沟能力，执行阶段保持禁用。

## 推荐架构与数据边界

### 1. 观测证据与普通可通行图分开

保留现有FREE/UNKNOWN/BLOCKED及其膨胀算法。新增仅供跨沟诊断的证据对象：
地图revision、坐标系、观测时间、两岸支持区域、高程与误差、沟边界及其不确定度、
可用净空证据来源。缺测始终表示证据不足，不自动赋值为已知空域。

优先测试有有限高程沟底的已知坑；其高度差可作为负地形候选，但单层高程仍不能证明
沟上方整个机身和摆腿扫掠空间自由，洞穴顶壁、悬垂结构尤其不能由此排除。
P3已有方差/观测次数可作为质量证据的候选输入；接入前须核实单位、计数更新、
高度范围与时间语义，不能将其随意替代占据或自由空间证据。
缺少单元观测时间时，不以整张消息时间戳断言每格都新鲜。
第一阶段用独立合成夹具显式提供完整证据，不修改P3或生产适配器。

### 2. 生成有限数量的跨越候选

在可靠岸边提取成对起跨区与落脚区，优先接近沟法向的前进跨越，不做横移/跳跃。
必须分别记录：沿候选方向的实际沟宽、岸边退距、足端跨度、机身位移、两岸高差、
落脚区可用面积及置信边界；不能将这些量都用maximum_gap_width_m替代。
按物理距离计算宽度并叠加栅格/测量误差；名义30 cm边界不能无条件按可跨处理。
落脚区面积与退距阈值来自实际足尺寸、落脚误差和步态，当前不编造默认数值。
可为诊断设置显式的合成机器人模型，结果必须标注模型来源且禁止部署自动采用。

候选数量设上限，按岸边局部范围生成；缓存键包含地图revision、能力版本、端点和方向。
修订涉及两岸、沟内或扫掠空间时使证书失效；方向不可随意反转复用。

### 3. 动作认证与普通边分开

提出独立CrossGapCertificate，依次检查：
观测充分→两岸支持→宽度/高差/足端可达→落脚稳定与支撑转换→摆腿和机身扫掠→底盘能力。
每一步保留通过/拒绝/证据不足及原因，例如 UNKNOWN_EVIDENCE、LANDING_TOO_SMALL、
GAP_TOO_WIDE、SWEEP_UNVERIFIED、EXECUTOR_UNAVAILABLE；名称仅为设计建议，尚未加入API。
不允许起点3 m盲区假定为跨沟起落脚认证提供证据。

普通行走外接圆碰撞保持原样。独立跨越扫掠认证属于未来新增模型；在用户尚未同意
引入该模型且无真实足端/机身几何时，只能输出诊断候选，不能发可执行成功证书。
将来接入搜索时，跨沟边应带动作类型、非负代价与独立认证；路径简化器不得抹掉动作边界。
启发式需保持对新增边代价的下界，否则不能沿用现有最优性假设。

### 4. 输出与执行契约

未来动作段至少携带类型、起止位姿、证书/地图/能力版本、执行前置条件、阶段与结果。
不能把跨沟段降格成普通nav_msgs/Path交给当前Pure Pursuit跟踪器。
控制端未声明受支持的跨沟动作时拒绝下发，普通导航继续绕行或报告无路。
跨越开始前可因证据过期取消；运动中失效时采用底盘定义的恢复/落脚策略，不能假设
立即归零Twist即可安全中止。该契约依赖真实驱动，留在后续执行阶段解决。
探索可视化可展示候选，但未认证的另一岸不能计为当前可达探索目标。

## 分阶段验收

1. 离线诊断：完整高程→细图基线保持；新增已知沟/缺测区的候选与逐项拒绝原因。
   未接真实几何和执行器时，任何几何候选均保持不可执行。
2. 合成模型认证：提供明确足尺寸/可达域/稳定性及三维障碍夹具，验证证书，
   通过仅代表合成模型；普通规划、轮式和TCP结果保持原有语义。
3. 规划与协议集成：独立动作边、revision失效、后处理保留、执行能力握手，默认关闭。
4. 真实驱动/仿真/Orin：拿到步态能力与恢复契约后分别验收，不从离线结果推断实机通过。

测试矩阵至少覆盖：平地对照，已知坑/NaN同形状对照，5/10/20/30/35 cm沟，
横向/斜向/曲折沟，落脚台不足、边缘缺测、岸边倾斜、不同上下高差、沟上横梁，
连续踏石、多步支撑转换、地图更新、定位误差、起点盲区与执行器缺失。
0.05/0.1/0.2 m记录真实栅格宽度及亚格偏移，防止采样消失被当成跨越成功。
记录候选数、分阶段认证耗时、规划p50/p95及峰值内存，沿用相同地图/CPU/构建条件。
