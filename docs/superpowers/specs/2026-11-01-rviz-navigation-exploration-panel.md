# RViz 导航与探索统一操作设计（已确认）

用户选择 RViz 操作面板。此设计属于下一批，静态 TF 接收修复先单独完成。

## 方案与职责

保留现有 RViz 显示、nav1cm 导航 Action、前沿探索任务话题和状态话题。增加一个小型 RViz 面板与区域选取工具；不建设独立网页和网络桥接，不增加导航状态机，不由界面发布车辆速度。

导航服务常驻，探索节点随导航启动但默认为 IDLE。启动程序不等于启动探索，必须显式选区并开始。探索只选择目标，导航负责路线、局部参考、执行与到达判定。共享基础地图设计保持暂停。

## 操作

- 地图上点击多个点绘制探索区域，闭合后显示区域轮廓及面积；点击开始探索发布已有 START 命令。
- 导航位姿沿用 RViz 点选位置和拖拽朝向；不重复实现规划或到达判定。
- 自主探索中选手动导航目标，暂停探索并保留区域，再交给现有导航入口执行；探索不能自动抢回目标。
- 暂停探索使用现有 PAUSE，取消其活动导航；仅取消探索自身持有的目标，不影响之后的手动目标。
- 恢复探索显式点击 RESUME，按当前地图和位置重新选目标；手动导航仍活动时需明确替换，不并行抢占。
- 结束探索使用 CANCEL，清除探索任务；导航目标取消使用对应导航入口，不混淆两个操作。

## 显示

复用地图、车辆位姿、全局路径、局部参考、探索前沿和区域标记。面板显示探索状态、覆盖率、当前目标及具体等待原因；导航状态独立显示。位置来源仍为 P3，控制域仍为 10。

## 实现边界与验收

现有 START / PAUSE / RESUME / CANCEL 及状态消息足够，优先复用。先核对手动目标替换、暂停回执与迟到结果，不引入新的任务或权限实体。以现有 Action 目标归属进行取消。

分批实施：常驻空闲与运行中启停 → 手动目标与探索交接 → RViz 面板和多边形工具 → 联调验收。每批独立复审。

必须验证：导航不重启即可开始探索；探索中可发手动目标且不被抢回；暂停/恢复保留区域；连续点击和迟到结果不会取消错误目标；显示实际原因；界面关闭不自行结束导航；无有效区域不能误发 START。Humble 构建与 DDS 操作验证先行，P3/车辆运行单独记录。
