# 局部规划软周期与计算复用

本设计是 NAV-1CM-20261026 的后续修订。用户已明确授权取消因超过 50 ms 就制动的机制，并继续优化计算效率；旧设计中对应的硬时间门禁由本设计替代。继续使用原专题工作树，不提交、合并、推送或接入实车。

## 行为

50 ms / 20 Hz 保留为期望周期和性能统计。只要候选和实际执行前缀通过当前地图、路线、底盘约束、实测初态、连续碰撞与停车尾段检查，就允许执行，即使计算超过 50 ms。时间统计不能改变轨迹有效性；求解失败、目标拒绝、候选不安全等仍使用经过重新认证的受限制动，不能瞬时置零。

本轮保留同步离线 tick 与异步全局 worker。取消硬门禁直接解决已测离线闭环的频繁时间制动；真实控制线程独立执行、求解期间的反馈更新和延迟补偿属于后续 ROS 接入边界，不由同步模型推断通过。避免本次同时引入新的线程调度模型而混淆性能比较。

## 计算复用

1. 地图模块管理距离场缓存。复用依据为实际可通行位图、shape、分辨率和未知策略；占据几何相同可复用距离及梯度数组，但必须产生绑定当前 epoch/origin 的场和当前 grid digest。窗口始终严格居中，不量化位置，不改 1 cm 分辨率。任何障碍变化必须反映到位图。
2. 认证模块准备一次绑定完整 grid digest 和 backend 的危险格索引，供完整候选、动作前缀和必要制动认证共同使用；每条轨迹仍独立验证动力学、扫掠与停车尾段。禁止把原轨迹的证书直接用于前缀。
3. 仅在测量支持时优化 NumPy 分配或重复循环；不降低认证精度、不删除慢样本、不降低地图精度。

## 验证

确定性时钟测试证明超周期仍执行有效移动轨迹，且不出现仅因时间触发的制动。拒绝候选、地图换版、未知禁行、目标变障等测试继续通过。缓存分别测试同几何不同 origin/epoch 的正确绑定、薄障碍和未知策略改变的失效、复用结果与无缓存结果一致。

Orin 使用已准备的 acados 与 native geometry；先跑真实求解测试，再在原多弯、短绕障和增障场景做有界回归（地图不超过 100 m，实际沿用 25 m 地图）。保存全部时延与安全审计，比较原始证据和本轮结果。50 ms 超时率继续报告，作为性能指标；到达、失败和资源停止分别报告。P3、ROS 节点、真实执行器及实车为 NOT_RUN。

## 测量驱动的距离场核心优化

缓存版已在三个高档闭环到达，但整体 P95 64.9 ms，距离场重建 P95 24.1 ms。继续增加可选原生距离场后端：以二维可分离精确平方欧氏变换计算占据格中心距离，再执行原有半格对角线减项、窗口边界裁限与同定义梯度。保留 SciPy 作为默认参考实现，原生库须显式指定，二者逐点对照；不使用近似距离或降低地图分辨率。原生后端只实现栅格数学，不负责调度、规划或认证。
