# 基于深度强化学习的机器人探索完整方案

日期：2026-09-08。

状态：完整设计提案，供审阅；本次仅维护方案文档，策略、训练环境及下文建议的新接口尚未实现。

源码核对基线：integration/pure-planner-orin，df469d16fcc46d633ac772e30b368967771e1c30。
文档分支：feat/drl-exploration-complete-design。当前方案不依赖 Isaac Sim 或 Isaac Lab。

## 1. 目标与已确定约束

学习一个根据增量可通行性地图、任务范围和平台位姿选择下一观测目标的策略。
策略输出连续平面位姿，现有导航器、规划器和控制器负责执行。训练从开始就使用这些现有模块。

| 项目 | 本方案选择 |
| --- | --- |
| 任务环境 | 月表、熔岩洞；首版采用单层地面高程和二维遮挡表示。 |
| 覆盖对象 | 任务多边形内已获得有效地图观测的水平投影面积，包含实际观测到的障碍格。 |
| 优化优先级 | 覆盖达标率和最终覆盖率优先；达到相近覆盖水平时，实际累计路程越短越好。 |
| 时间 | 无任务时间预算；训练采样截断、软件故障超时与探索任务结束分别处理。 |
| 任务范围 | 用户已确认典型宽度 100～300 m，最大约 1 km；复用现有角点、多边形校验和点在多边形内的判定。 |
| 区域外绕行 | 用户已确认允许；区域外移动产生路程成本，从区域外看到的任务内面积仍计入覆盖。 |
| 模拟观测初值 | 用户已确认有效距离 10 m、水平视角 90°，通过配置调整；这不是课题三实际视野的标定结果。 |
| 训练地图来源 | 首版以程序生成月表与单层洞穴场景为主，不依赖下载外部地图；真实地形可后续补充验证。 |
| 地图输入边界 | 课题三有效局部地图只由现有地图模块处理；策略不订阅课题三原始地图或原始传感器。 |
| 策略动作 | 连续目标位姿 (x, y, yaw)，不选择离散前沿编号，不将输出吸附到前沿。 |
| 地图变化 | 保留地图的增量积累和空间扩展，网络不要求输入整图尺寸固定。 |
| 局部输入 | 复用导航器的局部窗口配置、fine 分辨率和裁剪几何，避免另设冲突尺度。 |
| 中断续训 | 恢复学习器状态与限量经验，进程重启后默认开启新的探索回合。 |
| 并行环境 | 正式训练固定 8 个独立仿真实例，共享一个 GPU 学习器。 |
| 自动保存 | 按用户最新要求每 30 分钟保存一次；正常退出或可处理的人工中断时额外保存。 |
| 存储位置与保留 | 项目内 training-output/drl-exploration/，由 Git 忽略；固定文件名覆盖更新，限定总容量和写入峰值。 |
| 当前交付 | 方案与实现边界；不安装仿真平台，不运行训练或控制车辆。 |

首版训练采用现有轮式平台配置，学习高层探索，不学习轮速、转矩或足端控制。
足式平台后续需接入相应执行模型并单独训练或增加平台条件，不能将轮式训练结论直接外推。

## 2. 整体架构与数学建模

从学习角度，这是部分可观测、动作持续时间不固定的探索问题。
完整场景仅存在于仿真环境中；平台每次只能获得视野内的有效地图。
累积地图、过去的动作及导航反馈共同构成策略可用的信息。

在第 k 次高层决策时：

~~~text
观测 o_k = {派生地图 M_k，任务 T，平台位姿 p_k，必要的任务配置与执行反馈}
动作 a_k = 连续目标位姿
执行结果 = 导航器的一次目标执行，包含多个规划、控制和观测周期
奖励 r_k = 新增实际观测收益 - 实际路程成本 - 明确的无效动作成本
下一观测 o_(k+1) = 本次动作结束后已处理完成的地图与状态
~~~

这是高层半马尔可夫决策过程的建模方式。低层软件仍按自己的周期运行；
不要求每次策略决策等于一个控制周期，也不需要导航器、规划器或地图模块可微分。

~~~mermaid
flowchart TD
    W["场景真值与运动模型"] --> V["扇形视野与遮挡"]
    V --> G["模拟有效局部 GridMap"]
    G --> M["现有唯一增量地图模块"]
    M --> O["派生地图与观测有效性"]
    O --> P["探索策略：地图、任务、位姿"]
    P --> A["连续目标位姿"]
    A --> N["现有 NavigateToPose 与规划器"]
    N --> C["现有路径跟踪控制器"]
    C --> W
    W --> S["位姿、TF、执行里程"]
    S --> N
    S --> C
    S --> P
    O --> R["覆盖统计与奖励"]
    S --> R
    R --> L["强化学习训练器"]
    L --> P
~~~

任务管理器负责目标阈值、暂停、恢复和取消；策略只负责产生探索目标。
场景真值可以用于生成观测、检测碰撞和离线评估，不能直接写入策略地图。

## 4. 训练环境

### 4.1 软件组成

采用“轻量几何仿真 + 完整现有 ROS 2 软件闭环 + Gymnasium 风格训练适配器”。
轻量化发生在场景、传感器和运动模拟，不替换现有地图、导航和规划算法。

训练目标环境为 Ubuntu 22.04、ROS 2 Humble；Python/PyTorch 训练进程可与 ROS 适配进程分开。
本机 Jazzy 只作为隔离开发通道。训练进程的依赖版本在开始实现时锁定，
不要求为了训练改变生产 ROS 发行版或混用 overlay。

建议组件分工如下，名称是拟新增组件，不是已有接口：

| 组件 | 职责 |
| --- | --- |
| SceneGenerator | 生成地形、遮挡、碰撞边界、任务多边形和起点；固定随机种子。 |
| VisibilitySimulator | 根据真实模拟位姿、扇形和遮挡输出有效局部地图。 |
| MotionPlant | 接收现有控制器速度输出，推进位姿，检测实体碰撞。 |
| RosExplorationEnv | 完成 reset、step、消息同步、目标提交及反馈收集。 |
| PolicyMapExporter | 在地图所有者一侧导出只读派生视图，附版本和有效观测。 |
| CoverageMonitor | 按固定世界格键计算面积、首次观测、排除估计和任务结果。 |
| PolicyTrainer / PolicyRuntime | 分别负责训练更新和部署推理，共用预处理及动作解码。 |

本文的“一个环境”指一套可独立 reset/step 的探索仿真实例，包含场景地图、任务范围、
模拟机器人位姿、观测与累积地图、导航/控制执行、覆盖统计和采集器状态；首版每个实例只有一台模拟机器人。
例如 8 个环境是 8 次同时进行的独立探索任务，采集经验共同训练一个策略，并非限定训练只能使用 8 张地图。
每轮 reset 可以从生成器选择新的场景和起点，训练场景数量与同时运行的环境数量分别配置。
不同实例可以使用不同地形，也可以复用同一只读场景布局并设置不同起点；
各自的增量观测地图、导航会话和探索进度不共享，不能提前获得其他实例已经观测到的信息。
“唯一地图所有者”指每个实例内部唯一；实例之间通过 env_id 及隔离的 ROS 通信区分。

### 4.2 场景表示

每个场景包含：

- 地面高程 H(x,y)，以及可供现有可通行性模块判定的台阶、坡面和粗糙地形。
- 实体碰撞几何及平台允许活动的区域 D。
- 视线遮挡掩码 B_occ；与碰撞和可通行性分别定义。
- 任务多边形 T；T 是计数边界，不是遮挡墙。
- 起始位姿、平台尺寸、速度与转向限制、传感器配置。

场景 D 应包含任务外的绕行空间。场景外是仿真活动范围边界，不能画成一圈“已观测障碍”
来提高覆盖率。任务生成器可以产生有洞口、环路、窄通道、死胡同和封闭未知区域的场景。

首版洞穴表达为单层地面与平面遮挡，不声称处理多层洞穴、悬垂几何、洞壁及洞顶的三维表面积。
后续若引入三维几何，只替换环境中的可见性和运动后端，保持任务和策略接口。

#### 4.2.1 任务尺度与场景活动范围

用户已确认任务的典型宽度为 100～300 m，最大约 1 km。生成器将尺寸参数解释为任务多边形
轴对齐包围盒的较长边 L_T=max(width,height)，实际覆盖面积仍按多边形计算，不能把宽度当作面积。
训练以 100～300 m 为主要分布，再加入 300～1000 m 的课程；小场景用于初期校准。

场景活动范围 D 必须容纳 T、有效起点以及预设的任务外绕行线路，不能简单裁剪成任务包围盒。
生成器先构造地形与连接关系，再选取任务多边形；需要绕行的测试应确认外部通道没有被 D 截断。
传感器量程、导航局部窗口和全局 tile 尺度不随任务宽度等比例放大。

以 0.2 m 细分辨率计算，1 km × 1 km 有 2500 万格，单个 float32 通道约 95.4 MiB；
这是未含任务外区域、地图字段、版本、回放和网络激活的单通道大小。
因此真值优先用可查询的地形函数、几何基元和空间索引表示，细高程按观测窗口或 tile 按需采样。
新增观测仍由现有地图模块积累；不能为减内存丢弃已知地图或远处任务区域，也不能假定稀疏地图在
接近全覆盖时仍很小。8 个环境的 1 km 高覆盖状态、历史版本与保存峰值需要专门测量。
资源不足按第 4.6 节缩减回放、暂存或暂停，不静默减少环境数。

#### 4.2.3 首版程序生成场景

| 场景族 | 生成方式与变化 | 需要学到的行为 |
| --- | --- | --- |
| 月表 | 连续起伏底面，叠加不同尺度的陨坑、坑缘、岩石簇、坡面和局部粗糙区域；按单位面积配置密度。 | 绕开不可通行地形，变换视点观察遮挡后方，在开阔区避免重复往返。 |
| 单层洞穴 | 先生成连通图，再形成有宽度的洞道、洞室和分支，加入回环、死胡同、窄口、岩柱和封闭区域；叠加地面高程。 | 在分支间返回、穿过可通行洞口、绕行进入新区域，并识别仍可从外侧观测的障碍。 |
| 定向困难场景 | 构造任务外连接两入口、长已知通道、部分遮挡的不可进入区域、细窄通道等。 | 验证覆盖统计、不可观测排除、长程返回和导航失败处理。 |

初期用较简单月表校准，混合阶段建议月表与洞穴按 1:1 抽样，比例可配置；同一策略训练两类场景。
这是课程初值，不是用户必须另行确定的业务参数，也不要求 8 个环境永久各绑定一张地图。
地形随机性由 scene_seed 和生成器版本控制，任务形状、起点和朝向使用可追溯的独立随机子流。
生成器先保证起点 footprint 合法、首次有效观测足以初始化现有地图/导航，再校验至少存在有意义的
可探索区域；不要求任务内所有格可到达或可观测，不为强制 100% 覆盖删除封闭区域。
可通行性必须由现有平台配置和有效高程派生；遮挡 B_occ 来自几何近似，不能直接取膨胀后的 BLOCKED。
真值、观测模拟和碰撞几何之间的不一致应作为场景缺陷修正，不靠给策略完整地图来规避。

每次 reset 按种子生成或查询场景真值，然后沿实际运动生成局部观测：

~~~text
种子与场景参数 → 地形/遮挡真值 → 10 m、90° 扇形及视线检查
→ 模拟有效局部 elevation GridMap → 现有唯一增量地图模块
→ 已观测的派生可通行性、观测标记 → 策略输入
~~~

初始未知状态由观测决定，不预先把完整地形或可通行性真值交给导航器或策略。
仅保存生成器代码、配置和小型种子列表；训练不逐回合导出整图，回放仍保留其所需的历史观测数据。

#### 4.2.4 是否下载外部地图

首版不需要外部地图数据集、纹理或三维资产包。程序生成可提供足够多的布局变化，
便于控制通行性、遮挡和任务外绕行，并适配项目内的有限存储预算。
算法闭环稳定后，可选少量真实高程或外部洞穴几何作补充验证，不能据此代替实地验证。

### 4.3 扇形观测

用户已确认首版 R=10 m、φ=90°，二者都可通过配置调整；这是有效地图观测模拟初值，
不等同于相机标称视场或课题三真实有效地图范围的标定结果。
安装偏角、更新率与丢测范围先按第 14 节初值校准，后续以实际有效地图行为修正。

设平台朝向为 ψ，传感器安装偏角为 β，量程为 R，水平视角为 φ。
格中心 c 进入观测候选范围，当且仅当：

~~~text
distance(c, sensor_position) ≤ R
abs(wrap(bearing(c) - ψ - β)) ≤ φ / 2
~~~

然后检查视线：

1. 从传感器位置向格中心做二维射线遍历。
2. 前方遇到不透明遮挡时，遮挡之后的格保持未知。
3. 射线命中的首个遮挡格本身可以被观测，计入覆盖。
4. 可见且获得有效高度证据的格写入局部 elevation；其余格保持 NaN 或接口约定的无效值。
5. 模拟丢测时，无效格不进入有效观测标记。

首版明确采用二维不透明遮挡近似；不从膨胀后的不可通行地图直接生成遮挡。
坡面不可通行不代表它一定遮挡视线，低矮障碍的跨越观察若需表达，应改用高程视线模型。
统计按格中心可见与有效证据计算，是栅格面积近似，不声称整个格面每一点均被看见。

沿机器人实际运动轨迹按观测周期持续更新，不能只在目标到达后观测，也不能把整个扇形直接涂为已知。
更新后的模拟局部 GridMap 经过现有适配与增量派生链；不直接裁剪完整可通行性真值交给策略。

### 4.4 运动与初始化

首版轮式运动模型接收控制器给出的 v、ω，施加平台配置中的速度、角速度和加速度约束后积分：

~~~text
x_(n+1) = x_n + v_n cos(ψ_n) Δt
y_(n+1) = y_n + v_n sin(ψ_n) Δt
ψ_(n+1) = wrap(ψ_n + ω_n Δt)
~~~

使用平台 footprint 和运动扫掠检测碰撞，必要时细分积分步；发生碰撞停止运动并记录原因。
第二阶段可加入速度响应延迟、有限滑移和控制偏差，不把完整刚体动力学真实性作为首版结论。

初始已观测地图必须有来源：可由同一视野模型重放一段合法起步观测历史生成，
或使用明确提供的起步局部地图。不得自动给起点周围增加全向“已知自由圆盘”。
初始观测记为 O_0，不作为策略新增奖励；所有对照算法使用相同初始地图。
初始地图不足以满足导航器启动条件时，返回输入未就绪，不能通过伪造地图强行启动。

### 4.5 时钟、同步和重置

现有导航节点含 wall timer，控制器用单调时钟判断输入超时；设置 use_sim_time 并不自动得到
可任意加速、暂停的训练闭环。首个完整版本按实际可处理节拍运行，随后再测量瓶颈并实现一致的调度。
规划计算超时是软件保护机制，不能因为“任务不限时”就全部关闭。

每次 step 的完成屏障包含：本次目标已结束或取消确认、位姿有效、
截至选定观测序号的局部地图已经处理、对应派生视图已经可读。
地图模块需要提供“输入已处理”的确认，重复观测导致版本不变时也必须能够完成屏障；
不能等“地图版本必须增长”或“覆盖必须增加”，否则在已知通道内会死锁。

每轮 reset 需要同时重置场景、位姿、运动状态、累积地图、地图 epoch、
导航会话、活动路径、覆盖账本、执行历史和网络隐状态。
现有 START 任务消息不等于清空导航器的 PersistentElevationMap。
首个版本可以重启独立环境进程保证状态清理；后续显式 reset 接口需验证旧消息不会污染新一轮。

每个并行实例隔离 ROS domain 或全部 topic、TF 和时钟，并拥有自己的地图和导航状态。
训练控制器仅输出到该实例的模拟平台；不连接生产底盘话题。

## 5. 地图、观测与覆盖面积

### 5.1 可通行性和有效观测分开

地图模块提供两种不同信息：

- C_k(c)：当前可通行性状态和代价，含 FREE、BLOCKED、UNKNOWN。
- O_k(c)：截至当前，在本地图 epoch 中是否已有有效局部地图证据。

已有高度但邻域不足时，可通行性可以仍为 UNKNOWN；footprint 膨胀也可能让没有直接观测的格
变为 BLOCKED。因此不能以“C 不等于 UNKNOWN”严格代替 O。

O 由地图模块根据有效局部证据积累，可作为派生视图中的一层；
策略不为此订阅课题三数据，也不重建第二份高程或可通行性地图。
只有上游确认有效的观测才置位；若上游为未观测区域填入插值高度，需有效性契约才能区分。

首版在固定 map frame、冻结分辨率 r 的条件下，以世界栅格坐标识别同一物理格。
地图滑动、数组原点变化、tile 重新发布和重复观测不产生新的物理格。
如地图 frame 被整体校正，必须做一致的历史重映射或开启新 epoch，不能继续沿用旧格键。

### 5.2 指标定义

令 T 为格中心落在任务多边形内或边界上的固定世界格集合，单格面积为 a=r²。
任务超出当前已分配地图的部分仍属于 T，且在没有证据时为未观测。
令 U_k=T\O_k，X_k 是 U_k 中按简化规则估计可排除的集合。

| 指标 | 定义 |
| --- | --- |
| 任务面积 A_T | \|T\| a |
| 已探索覆盖面积 A_O(k) | \|T ∩ O_k\| a |
| 未观测面积 A_U(k) | A_T - A_O(k) |
| 估计排除面积 A_X(k) | \|X_k\| a，X_k ⊆ U_k |
| 估计可探索覆盖面积 A_E(k) | A_T - A_X(k) |
| 估计剩余可探索面积 A_R(k) | A_E(k) - A_O(k) |
| 原始观测覆盖率 C_task(k) | A_O(k) / A_T |
| 估计有效覆盖率 C_eff(k) | A_O(k) / A_E(k) |

恒等式为 A_T=A_O+A_U、A_E=A_O+A_R，且 0≤A_X≤A_U、0≤A_O≤A_E≤A_T。
无效任务和零分母不能宣告完成。

例如，任务 10000 m²，已观测 8000 m²（其中实际观测障碍 2000 m²），
未观测中估计排除 1000 m²，则 A_E=9000 m²，A_R=1000 m²，
C_task=80%，C_eff≈88.89%。被排除的部分仍是未观测，不计入 A_O。

先前覆盖定义文档位于 feat/exploration-coverage-definition 的提交 036ad64，
文件名为 2026-09-08-exploration-coverage-definition-design.md。
其 A_K=(known_free+known_occupied)r² 是现有三值地图的已知面积近似。
本方案延续面积之间的关系，但训练主指标改为有有效证据的 A_O。
旧 coverage_ratio 和已知面积字段不静默改义；新统计需要新字段并带 metric_version。
两种口径只在有效观测与分类一致时相等，历史数据不能直接混合比较。

### 5.3 封闭区域的排除估计

保持先前接受的简化思路，但结果始终标为“估计”，不声称证明不可观测。
在完整当前地图上，FREE 和 UNKNOWN 作为潜在连通区域，BLOCKED 作为二维屏障，做八邻域分量标记。
只对不属于平台分量、且不接触当前地图边缘的分量，提取其中任务内未观测格作为 X_k。

为防止坐标和分辨率混淆，连通掩码与 O、T 必须对齐到同一统计格几何。
若使用粗格辅助计算，只能将充分满足规则的整格区域映射回细格，不把部分细格证据扩张成整格已观测。
平台种子不可用、分量接触地图边缘、地图外未知、未知通道尚连通时均不排除。
未观测但被膨胀标记为 BLOCKED 的格不会因此自动变成已观测或被自动排除。

连通分析包含任务范围外的地图，任务边界不参加障碍封闭判断。
排除仅保存为估计掩码，不能修改 C 或 O；后续发现通道时可以撤回排除，C_eff 可以下降。

可通行性 BLOCKED 可能来自坡度、低矮障碍或 footprint 膨胀，不能严格证明视线被挡。
建议后续由地图派生侧使用未膨胀的遮挡证据提高估计质量。
在不接受“BLOCKED 近似不透明屏障”的场景关闭排除，令 X=∅，保留原始覆盖率及未达标状态。

首版可完整重算，复杂度 O(N_map+N_task)。大图使用 tile 和世界格索引组织数据；
遇到未分配区域时保持开放未知，不把稀疏存储空洞当成障碍。

### 5.4 仿真参考可观测面积

离线评估可使用真值额外估计“平台能够到达的观测位姿的可见区域并集”：

~~~text
E_ref = T ∩ union V(q)
        q 遍历活动区域 D 中按平台几何可达的采样位置和朝向
C_ref = |O_k ∩ E_ref| / |E_ref|
~~~

可达采样位置需要考虑平台 footprint、运动约束和区域外绕行；
V(q) 包括可见障碍，不能用“可达自由面积”代替“可观测面积”。
这是位置和朝向离散采样得到的评估参考，不是连续空间的精确理论上限。
必须记录采样步长与角度，报告 O_k 落在 E_ref 外的面积以检查参考集合漏采样，
不能直接以 A_O/|E_ref| 后裁剪到 100% 掩盖问题。
E_ref 不进入策略、在线排除或导航器，只用于比较真实观测能力和估计达标误差。

## 6. 策略输入与不断扩展的地图

### 6.1 输入内容

主体输入保持为地图、任务范围和平台位姿。地图侧提供以下通道：

| 通道 | 用途 |
| --- | --- |
| FREE / BLOCKED / UNKNOWN | 当前可通行性三种状态，独立编码，避免把 UNKNOWN 当成低代价自由区。 |
| TraversalCost | 现有模块派生的连续通行代价，仅在有效状态下使用。 |
| Observed | 有效观测标记 O，区分尚未观测与已观测但尚不能完成通行判定。 |
| TaskMask | 任务范围，区域外仍保留地形信息以支持绕行。 |

小维度附加状态包括平台位置与 sin(yaw)、cos(yaw)、平台在局部窗口内的位置，
上次实际发送的目标、导航结果及实际位移。
这些是任务运行反馈，不是新增传感器输入。无需输入原始 RGB、点云、完整真值地图或前沿候选列表。

量程、FOV、平台配置在一个训练任务中固定时可以作为模型配置；跨这些参数随机化训练时，
将相应参数作为任务级条件输入，使训练与部署能使用同一解释。
覆盖目标变化较大时一并输入目标阈值；由任务管理器判断是否结束。

PolicyMapExporter 从同一地图所有者的快照派生数据，建议携带：
map_epoch、map_revision、坐标原点、分辨率、tile 世界索引、观测处理序号和有效性。
这些是拟新增协议字段，不是假定现有 OccupancyGrid 已包含的信息。
全局和局部策略视图来自一致快照；不要把不同 revision 的数据拼成一个状态。

### 6.2 多尺度、分块地图编码

推荐使用“全局分块 CNN + 局部精细 CNN + 注意力汇聚 + GRU”。
这是本项目的设计选择，具体尺寸是起始配置，需通过消融验证收益。

全局分支保留固定物理分辨率，例如 1 m，每个 tile 覆盖 32 m × 32 m。
共享 CNN 把每块编码为空间特征，保留块内子区域的位置；不能把整块仅压成不带位置的一个平均值。
全局聚合采用 fine FREE/BLOCKED/UNKNOWN 比例、observed 比例及有效代价统计，
不会把 coarse FREE 解释成整块已观测或整块可通行。

全局输入至少覆盖全部任务 tile 和当前地图已经扩展到的任务外 tile。
尚未分配的任务 tile 使用明确的 UNKNOWN 表示，不因地图尚未扩展到该处就从输入消失。
区域外可继续探索和绕行；当前地图边界不是场景障碍。

局部分支复用导航器的局部窗口，不再单独设置 32 m 的策略窗口。
窗口边长继承 config/exploration_navigation.yaml 中的 navigation.local_window_size_m，
当前为 64 m；分辨率取同一 fine snapshot，而非在探索配置中另行指定。
输入为 0.2 m 时，请求窗口为 320 × 320 格；输入为 0.1 m 时为 640 × 640 格。
首版模型以 64 m、0.2 m 作为训练配置，其他组合需要验证后写入模型支持范围。

复用 BuildLocalPlanningWindow 的世界格索引、原点、map 轴对齐和边界裁剪规则，
用决策时的一致地图快照与平台位置构造窗口。靠近地图边界时窗口会偏移，
当前 fine 范围不足时实际窗口会小于请求尺寸，不能假定平台始终位于图像中心。
较小窗口补齐到模型输入尺寸，附带有效范围掩码和裁剪原点；缺失地形编码为 UNKNOWN，
TaskMask 仍按对应世界坐标计算，补齐本身不代表新增地图或观测。
导航器在执行期间继续重规划，不要求后续每次规划都使用策略决策时的旧窗口。

统一的是地图来源、物理尺度和几何语义。策略另外读取 Observed、TaskMask 等任务通道；
CNN 可在网络内部用步幅卷积降低特征尺寸，不改变导航器细地图或输入物理范围。
相对原 32 m 窗口，64 m 窗口的输入格数增加到 4 倍，应先减少 batch 并测量显存。
全局分支的 32 m tile 是独立的分块尺度，继续保留。

给全局特征加世界位置、相对平台位置和块内位置编码；通过固定数量的 latent query
对可变长度 tile token 做 cross-attention，得到固定维度全局表示。
例如 32 个 query、特征维度 128，避免对全部细地图格做平方复杂度的全局 self-attention。
可参考 Perceiver 的非对称注意力思想，但这里对探索地图的适配效果需要自行验证。[R6]

~~~text
全局 tile 集合 → 共享 CNN + 位置编码 → cross-attention → 全局特征
局部 fine 视图 → CNN --------------------------------→ 局部特征
位姿、任务参数、上次目标与结果 → MLP -----------------→ 状态特征
                                  三路融合 → GRU → Actor / Critic
~~~

GRU 保存决策与失败历史；累积地图承担主要的空间记忆，不要求 GRU 记住整张地图。
Actor 和两个 Critic 各自维护一致的序列状态，训练时的梯度和编码器共享策略需要显式定义。
首版优先分离 Actor 与 Critic 的循环状态；两个 Critic 可共享感知编码器但保留独立 Q 头。

不同 batch 的 tile 数量用 padding 和 attention mask 对齐；padding 不等于未知地图。
已知地图范围增长不会改变米与格的比例。坐标归一化使用固定任务参考原点和尺度，
不能随当前已知地图的 bounding box 改变，否则同一地点会不断换坐标。

网络支持可变 tile 数量，不意味着资源无限。超过部署验证过的地图规模时，
应报告输入规模不支持，或使用已经训练和验证过的分层汇聚方案；不能静默删除远处未探索区域。
推理时可按 dirty tile 更新特征缓存；训练时编码器权重变化后必须重算相应特征，
不能跨优化步骤复用旧神经特征并把它们当成当前编码器输出。

## 7. 连续动作与执行协议

### 7.1 动作参数化

首版 Actor 输出三个连续随机变量的均值和标准差，经 tanh 得到 u=(u_x,u_y,u_ψ)，各分量在 (-1,1)。
使用固定的动作尺度 d_a，解码为：

~~~text
[x_goal, y_goal]^T
    = [x_robot, y_robot]^T + Rot(yaw_robot) · d_a [u_x, u_y]^T
yaw_goal = wrap(yaw_robot + π u_ψ)
~~~

d_a 在任务开始时按任务尺度和运行配置确定并保持固定。
起始建议取 max(2R, 任务多边形包围盒对角线长度)，允许全局返回与较远目标；
动作超出仿真活动区域 D 时明确拒绝，不以 D 的真值障碍修正位置。
大范围连续动作初期会较多落在未知或不可达区，通过示范初始化和失败反馈学习有效目标分布。

策略可以输出任务外的目标以实现绕行，导航器按地图及平台约束判断可执行性。
Yaw 决定到达后的观测方向；位置几乎不变、主要改变朝向的动作也允许提交，
由现有导航和控制执行能力决定能否完成，不能直接改写模拟平台朝向。
Action 存在 yaw 字段、控制器存在末端转向逻辑，只能作为源码接入依据；
目标朝向是否完整通过规划参考传到控制执行，仍须按同位置转向和带末端朝向的移动目标验收。

部署初始采用 tanh 后的分布均值；训练时从分布采样，计算 log probability 时包含 tanh 变换修正。
位置与朝向尺度在部署清单中固定。朝向误差和示范损失使用周期角度距离，
避免把 -π 与 π 当成相差一整圈。

### 7.2 动作校验

动作适配器只做有限值、坐标系、配置范围和版本检查，再交给现有 NavigateToPose。
不把目标吸附到最近前沿，不在背后另选一个启发式目标，也不因“任务外”直接拒绝允许的绕行。
导航器保留现有平台通行、footprint、局部规划和可执行路径检查。

如果原目标被拒绝或规划失败，该尝试本身形成带结果的转移；
实际执行过的部分路程和实际获得的观测仍计入该步。
失败后允许基于同一地图版本提出另一个目标，不强制等待地图必须发生变化。

如后续引入目标修正、重采样或传统策略回退，必须记录 proposed_action、
executed_action 和控制来源，并按实际行为进行学习与独立评估；
不能把替换目标的收益记到原始目标上。首版不启用这种隐式替换。

### 7.3 一次 step 的定义

~~~text
step(a_k):
    确认当前无活动目标，读取一致快照
    解码、记录并提交连续目标
    持续运行地图输入、导航重规划、控制器及运动模型
    沿途按观测周期更新地图，累计新增有效观测与执行路程
    等待目标明确结束；如果任务途中达标，发出取消并等待停止确认
    等待地图输入处理屏障，收集最终快照与导航原因码
    计算奖励，区分任务终止与采样截断
    返回 o_(k+1), r_k, terminated, truncated, info
~~~

拒绝动作也必须产生明确结果与下一观测，不使用“循环采样直到有效，再只记录有效动作”的隐藏流程。
一次目标失败不是整个探索任务自动失败；输入不可用时则暂停采样或记录基础设施异常。

## 8. 优化目标与奖励

### 8.1 目标优先级

任务层首先提高覆盖目标达成率，并最大化结束或评估检查点的观测覆盖；
在达到相近覆盖水平的策略中选择总执行路程较短者。
不以完成时间作为目标，不要求最短直线位移，不奖励不可执行的预测信息增益。

训练中用加权奖励作为可优化的代理，评价和选模按覆盖优先。
有限权重的加权和不能严格保证数学上的字典序最优，不能仅凭 w_A>w_L 就声称“覆盖绝对优先”。

### 8.2 每步奖励

令 ΔA_k 是该动作期间任务内首次获得有效观测的面积；
ΔL_k 是该动作实际执行轨迹的累计平面长度，包含绕行、回退和失败前已经走过的部分。
取固定归一化尺度 L_ref=sqrt(A_T)，不使用随估计排除变化的分母。

~~~text
r_k = w_A · ΔA_k/A_T
    - w_L · ΔL_k/L_ref
    - w_I · I_invalid
    - w_C · I_collision
~~~

起始实验权重可取 w_A=100、w_I=0.05、w_C=5。
先用 w_L=0 学习观测覆盖和有效目标，覆盖达到验证基线后逐渐增加到 0.05～0.1；
这些是调参起点，不是已经验证的最优配置。
经验池保存奖励分项，在采样时用当前阶段权重组合，避免把不同权重下的总奖励混用。

I_invalid 表示明确无效的策略目标或正常工作条件下的不可执行目标；
资源过载、DDS 断连、地图适配错误等不自动算作策略错误，按基础设施原因记录。
I_collision 对应运动模型中实际检测到的碰撞，触发本轮失败。

奖励和统计必须遵守：

- 实际观测的障碍格与自由格一样产生首次覆盖奖励。
- 任务外自身面积不产生奖励；从任务外看到的任务内新面积产生奖励。
- 重复观测、数组扩大、tile 重发、地图版本增长本身没有奖励。
- X 增大或 A_E 缩小不产生覆盖奖励；首版不额外给予“估计覆盖达标”奖金。
- 在已知通道内正常移动即使 ΔA=0 也继续执行，不加“若干步无增益就失败”的惩罚。
- 首版路程指平台中心的平面轨迹长度；原地转向不虚构平移路程，可另报告累计转角。
- 每步不增加固定时间惩罚或生存奖励。

例如 A_T=10000 m²，某步新增 120 m²，实际移动 15 m，w_L=0.1，
无无效目标或碰撞，则奖励为 100×120/10000 - 0.1×15/100 = 1.185。

仅禁止分母变化的直接奖励仍不足以证明没有漏洞：提前按错误排除终止可能免掉后续路程成本。
因此验证必须检查估计排除误差和“估计达标而参考覆盖未达标”的比例。
发生系统性误判时应收紧或关闭排除，不能只调整奖励权重掩盖问题。

### 8.3 路程来源与折扣

无噪声仿真初期可由连续发布的模拟 odometry 积分：
ΔL=sum hypot(x_(n+1)-x_n, y_(n+1)-y_n)。
定位噪声实验需要固定里程估计办法，同时记录运动模型真实里程作为审计参考；
不能让噪声抖动变成主要路程成本。部署使用实际可获得的同口径里程，不使用计划路径长度替代。

任务的未折扣目标是累计新增面积与路程的组合。SAC 训练可先取 γ=0.999，按高层决策计步，
用于数值稳定和长程信用分配；这仍会对远期收益产生偏好，是训练近似而非严格未折扣最优。
不按物理耗时使用 γ^duration，也不把该折扣解释为任务时限。
需要用长通道返回场景检验折扣和距离权重是否使策略放弃远处覆盖。

## 9. 任务结束、饱和与异常

任务目标 τ 来自配置。开启有效覆盖估计时，用有效且同版本的 C_eff 与 τ 比较；
关闭排除时 C_eff=C_task。输出必须同时记录原始覆盖、估计有效覆盖和排除面积。
目标达成状态应说明使用的是原始还是估计分母。

| 情况 | 任务处理 | 训练语义 |
| --- | --- | --- |
| 覆盖达到配置目标 | 取消剩余活动目标并确认停止，记录 TARGET_REACHED。 | terminated=true。 |
| 仅若干周期没有新增观测 | 正常执行或继续选择目标，不能直接宣告结束。 | 非终止。 |
| 单次 NO_PATH / INVALID_GOAL | 记录失败和实际收益，允许选择另一个目标。 | 通常非终止。 |
| 当前估计无可执行的新观测位姿 | 记录 EXHAUSTED_ESTIMATE；覆盖未达标时明确报告未达标。 | 经独立检查确认后可结束为未达标回合。 |
| 输入缺失、通信故障、计算过载 | 等待恢复或中止该次采样，记录基础设施原因。 | 不当作覆盖成功；异常样本隔离。 |
| 真实模拟碰撞或平台不可恢复故障 | 停止并记录失败。 | terminated=true。 |
| 采样达到配置的决策数或资源上限 | 截断收集，保留最后有效状态；不宣告探索完成。 | truncated=true，正常截断保留 bootstrap。 |
| 用户暂停、恢复、取消 | 独立任务控制事件；暂停保留状态，取消停止。 | 与任务成功分别记录。 |

EXHAUSTED_ESTIMATE 不能仅由策略反复失败触发。首版建议使用独立、保守的可探索性检查：
在当前已知可通行连通区域采样可执行观测位姿，对未知区域做乐观视线增益估计，
检查是否仍有可能产生新增观测的位置，并确认没有活动导航或待处理地图。
检查使用整个当前地图，包含区域外绕行，不依赖策略本次选点结果。

该检查的位置和角度采样用于结束判定，不是策略动作空间离散化；
它不能证明连续空间或未来地图中绝无可探索位置，因此状态带 ESTIMATE。
如果只出现多次失败但不能完成上述独立检查，进入 STALLED/等待诊断，
训练收集器可以按资源上限截断，不能伪报探索耗尽或覆盖达标。

当前节点的 COMPLETED_NO_REACHABLE_FRONTIER 不能直接作为新策略的成功条件；
新模式应复用任务输入和导航协议，替换与传统前沿搜索绑定的决策、等待及完成分支。

正常采样截断与真实终止的 bootstrap 行为不同，见 Gymnasium 官方说明。[R7]
尤其要保存截断前的 final observation，不能把自动 reset 后的新地图作为旧转移的下一状态。

## 10. 强化学习算法与经验回放

### 10.1 首选 Recurrent SAC

推荐以 SAC 的连续随机策略、双 Q 和经验回放为基础，增加序列编码。
理由是动作连续，完整导航交互比单纯网格移动昂贵，复用过去交互有价值；
GRU 用来表达有限观测及动作失败历史。[R4][R5]

这是本任务的算法选择，尚未有该项目上的优于 PPO 的实验证据。
PPO 可作为同输入、同连续动作的算法对照。单次安装常规 SAC 库并给 Actor 加一个 GRU，
并不自动构成正确的 Recurrent SAC；Actor、Critic、回放和隐状态需要共同适配。

训练采用两个 Q 网络及目标网络。对序列历史 h 的目标值为：

~~~text
y = r + γ (1 - terminated)
        [min(Q1_target(h_next, a_next), Q2_target(h_next, a_next))
         - α log π(a_next | h_next)]
~~~

Actor 优化预期 Q 与熵的组合。α 是动作探索正则，不是实际覆盖奖励；
训练后期降低熵强度，评估采用确定性策略，检查是否出现原地反复变更目标的熵驱动循环。
普通无损截断保留 bootstrap；基础设施破坏了状态连续性的片段不强行套用该公式。

### 10.2 回放数据

每个高层转移在经验池中至少包含以下逻辑数据；不要求每项分别落盘或每步保存一份整图：

~~~text
env_id, scene_seed, episode_id, task_id, map_epoch
o_k 对应的不可变地图/tile 版本引用、局部裁剪几何、任务和位姿
proposed_action, executed_action, navigation_outcome, reason_code
新增观测面积、执行路程、奖励分项、动作持续时间
o_(k+1) 对应的不可变视图
terminated, truncated, final_observation, observation_sequence
~~~

回放在同一 env_id 内按连续序列抽样，以 burn-in 重建隐状态，再对后续片段反向传播。
跨实例、episode、地图 epoch 或重置边界切断循环状态，不能按消息到达时间把多个实例串成一条历史。
不能只保存旧 GRU 隐状态后永久复用；权重更新会使历史隐状态过时。
烧入段长度及隐状态近似误差应在长走廊、回环和多次失败场景中验证。

保存“当时可见”的地图，不允许使用当前最新累积地图重建历史 o_k，
否则会把未来观察泄漏到过去。原始地图按不可变 fine tile 版本去重，
分类与观测标记紧凑编码，连续代价保留已验证的精度，训练时再生成 one-hot 和多尺度视图。
能从该时刻的 tile、任务与裁剪几何重建局部输入时，不另存一份局部稠密数组。
不能仅保留有损的全局粗特征来重建 fine 视图，也不能用场景种子替代历史观测。

首版经验池放 CPU 内存，按总字节数限制；旧序列淘汰后用引用计数释放无人使用的 tile 版本。
索引、观测数据、版本依赖和序列元数据都计入容量，不只统计动作数组。
不建立持续增长的磁盘经验库；检查点只带自包含的限量回放子集，见第 11.4～11.5 节。

### 10.3 起始实验参数

| 参数 | 起始建议 | 说明 |
| --- | --- | --- |
| 高层动作维度 | 3 | 连续位置增量与朝向增量。 |
| 优化器学习率 | 1e-4 | Actor、Critic 分别记录损失和梯度。 |
| 折扣 γ | 0.999 | 高层决策折扣，非时间截止。 |
| 目标网络软更新 τ | 0.005 | 与任务覆盖阈值 τ 使用不同配置字段名。 |
| 序列 batch | 目标 8 条，比较 4/8/16 | 按完整网络、序列及地图规模的峰值显存与优化吞吐选择，不静默缩小窗口。 |
| 训练展开 / burn-in | 16 / 8 个高层转移 | 是起点，需要长程场景消融。 |
| 内存回放容量 | 目标 8192 MiB，上限 12288 MiB | 按需增长，含全部去重观测与索引；服从总主存预算。 |
| 检查点回放子集 | 上限 2048 MiB | 含所选序列的完整地图依赖；不要求将整池定期复制到磁盘。 |
| 隐状态维度 | 256 | 与地图编码器一起评估。 |
| 并行实例 | 固定 8 个 | 正式训练与续训保持一致，共享一个 GPU 学习器；不比较或自动调整环境数量。 |
| 训练 CPU 线程 | 算子内 8、算子间 1 | 比较算子内 4/8；独立于现有导航进程线程数。 |
| 显存 / 总主存目标 | 10240 / 20480 MiB | 主存还受启动时可用量减 4096 MiB 的约束；计入各环境与保存暂存。 |

更新次数与新样本数量要同时记录。较大的 update-to-data ratio 可能过拟合陈旧地图分布，
先采用约 1 次优化更新/新增高层转移的调度，再依据验证曲线调整。
训练的“步数”统一注明是高层决策数还是物理积分步，不能混用。

## 11. 从环境校准到策略训练

### 11.1 先验证环境和指标

先用固定小场景验证可见性、有效观测、导航执行和奖励是否一致。
至少包含障碍遮挡、原地转向、重复观测、任务外绕行、长已知通道、封闭未知区域、
地图扩展和动作失败前部分移动。

检查同一动作与随机种子能否重现接近一致的执行轨迹和面积。
ROS 调度可能导致时序差异，应在限量经验中记录高层动作序列、执行结果和处理版本；
不能仅固定随机种子就宣称整个异步闭环完全确定。
常规运行只落盘摘要指标，不为此持续保存控制周期、全部 odometry 或原始地图消息。

本阶段已有完整导航、规划和控制器，不用简化 A* 或瞬移替代。
传统探索器产生的目标也经过相同导航闭环，用于发现模拟地图是否会误触发不可通行判定。

### 11.2 示范初始化

用现有前沿探索器执行完整探索轨迹，将实际发送的目标转换为连续动作参数。
高层示范序列直接流入限量经验池，默认不另外导出完整轨迹数据集或 rosbag。
示范只提供训练阶段的观测—动作样本，不成为学习策略推理时的候选集合。
记录教师的失败和覆盖结果；行为克隆优先使用有效、执行一致的示范片段。

Actor 可以先学习教师动作分布：
位置采用归一化回归或负对数似然，朝向采用周期误差。
同一观测存在多个合理方向时，采用一致的教师规则或保留分布；
不能把两个分支目标简单平均后当成落在障碍中的“正确目标”。
若后续证实单高斯限制严重，可评估连续混合分布，属于网络消融而非改为离散前沿选择。

是否使用示范需要单独报告，并保留不使用示范的对照。
初始化阶段学习有效目标分布，后续仍由自主交互优化覆盖与路程。

### 11.3 覆盖优先的自主训练

采用从易到难的场景课程，所有阶段使用相同地图和导航闭环：

| 阶段 | 场景与扰动 | 主要检查 |
| --- | --- | --- |
| 起步 | 开阔月表、少量遮挡、固定量程及视角、无定位噪声。 | 是否能持续扩大有效观测，是否会转向扫描。 |
| 连通结构 | 多入口、障碍环、死胡同、回环、窄通道。 | 是否会返回已知路段并进入新分支。 |
| 地形约束 | 坡面、台阶、凹坑、不同平台可通行阈值下的固定训练配置。 | 是否依据派生可通行性选择可执行观测位姿。 |
| 范围变化 | 以 100～300 m 任务为主，逐步加入 300～1000 m、不规则任务与任务外绕行。 | 是否保留任务外地图并探索尚未展开区域，局部物理尺度是否保持一致。 |
| 鲁棒性 | 参数范围内的 FOV、量程、地图更新间隔、有限丢测、位姿与运动偏差。 | 是否对部署条件变化稳定，是否产生虚假观测。 |
| 泛化 | 未见拓扑、较大地图、新障碍布局。 | 是否依赖训练场景布局或任务归一化尺度。 |

初期让 w_L=0，保留无效目标和碰撞成本。
当验证覆盖稳定后逐步增加路程权重，并仅接受覆盖表现未明显退化的模型。
所有噪声幅度都必须与地图模块能够处理的契约一致；不要用过大的独立高度噪声
让累计高程极差永久扩大，从而把噪声误当作难地形学习。

进入较大任务课程前应检查采样决策上限是否足以产生接近目标覆盖的经验。
第 14 节的 1000 次仅是起始采样上限，不能不经验证固定用于所有 1 km 任务；
可按课程提高该上限，正常截断仍按第 9 节处理。完整任务评估不使用训练采样上限来判断结束。
同时验证长程折扣偏好和资源峰值，不能仅扩大地图就宣称具备 1 km 覆盖能力。

### 11.4 长程训练与恢复

默认支持恢复训练进度：加载最新学习器状态和限量经验，再开始新的探索回合。
进程重启时不恢复整套 ROS 现场、活动导航目标和累积场景地图，以控制存储量与恢复复杂度。
进程仍存活时的暂停可以保留内存环境；这与跨进程续训是不同机制。
训练采样截断、定期保存和用户中断都不等于探索完成，也不引入任务时间限制。

最新续训检查点 resume.pt 必须包含：

| 状态 | 内容与原因 |
| --- | --- |
| 学习网络 | Actor、感知编码器、GRU、双 Q 及其目标网络；不能只有推理 Actor。 |
| 优化状态 | 全部优化器状态、log α 及其优化器、学习率调度器、启用时的 AMP scaler。 |
| 训练进度 | 已提交高层转移数、优化更新数、回合计数、课程阶段和奖励权重阶段，恢复后继续计数。 |
| 随机与归一化 | Python、NumPy、PyTorch CPU/CUDA 随机数状态，归一化统计和场景种子生成进度。 |
| 限量回放 | 可训练的连续片段、烧入段、下一观测、边界标记，以及它们实际引用的不可变地图数据。 |
| 配置与标识 | checkpoint_schema、地图通道和窗口几何、动作尺度、metric_version、平台/传感器配置、代码与依赖版本、验证种子列表、最佳模型评分标识和载荷校验值。 |

优化器状态是恢复训练所需内容，不能为省空间只存权重却仍称为完整续训。[R8]
冻结检查点必须在没有优化更新进行的稳定边界进行；已开始的更新先完成，尚在初始采样时也可保存。
地图引用和已完成转移也要对应一致提交序号。
后台写入时不能直接引用仍被优化器修改的张量。

回放子集优先保留近期片段，并保留少量不同场景和课程的片段；按字节预算选择，
每段至少满足 burn-in、训练展开和下一观测要求，不必保存整轮长任务。
所需 tile 基版本、增量或完整版本必须全部在同一检查点内，不能只存索引或外部临时文件路径。
恢复后检查所有引用可解析，按序列重新计算循环状态。
子集会改变经验分布，因此不承诺与未中断、保留全部经验的训练逐步相同。
若预算内没有足够的完整训练片段，则明确报告需要重新收集经验，达到最小采样条件后再更新；
已恢复的网络、优化器和训练计数保持不变，不伪造缺失观测。

按用户最新要求，周期保存间隔为 1800 s（30 分钟），按训练进程的单调墙钟计时，
不按仿真加速时间或任务耗时计时；正常退出或收到 SIGINT/SIGTERM 时额外保存。
仅在状态有变化时更新同一个文件，不按 episode 或时间戳新增模型，计时从成功保存后重新开始。
验证发现更好的 Actor 时先在 CPU 内存保留一份包含权重、对应归一化和验证评分的候选快照，
随上述保存事件更新 best.pt，避免每次验证额外写模型；候选内存也纳入第 4.6 节预算。
定期保存可使用最近已完成的转移，不必等待一个远距离目标执行结束。
收到可处理的中断时，先停止发新目标，通过既有执行链取消模拟导航并确认停止，
只纳入已经获得有效下一观测的完整转移；无法完整结束的当前动作不写成半条经验。
已保留序列按最后有效状态结束采样，保留真实 terminated 标记及正常截断的 bootstrap 语义。
SIGKILL、断电或进程崩溃只能恢复最近一次成功保存；保存正常时可能丢失最近约 30 分钟的进度，
若保存失败或尚未完成首次保存，则以实际最后成功检查点为准。

重启后的恢复顺序如下：

1. 校验 resume.pt 的结构、载荷和配置兼容性。网络结构、地图语义、窗口/分辨率、动作解码或覆盖口径不兼容时拒绝静默续训；仅调整日志和存储预算不要求重训。
2. 恢复学习网络、优化器、训练计数、课程、随机状态、归一化及有效回放子集。
3. 通过环境 reset 屏障开启新 episode/map_epoch，清空现场地图、覆盖账本、活动路径和采集器 GRU；从保存的种子生成进度开始新场景，不将旧隐状态配给新地图。
4. 确认新环境输入就绪；回放足够则继续优化，不足则先采集。记录一次恢复摘要及丢弃的未完成动作数量。

resume.pt 缺失或损坏时明确报告无法完整续训，不自动把 best.pt 当作续训检查点。
best.pt 可用于推理或显式的新一轮权重初始化，但没有恢复原优化进度的能力。
首版不保存整环境快照；如未来要求中断后继续同一探索现场，需要另行设计并核算存储。

### 11.5 存储预算与文件保留

训练产物集中在 <项目根目录>/training-output/drl-exploration/，同一实验重启继续使用它。
启动器显式确定项目根目录，解析相对此根的 output_dir；从不同工作目录启动也必须得到同一个位置。
该目录已被 [.gitignore](../../../.gitignore) 忽略；由后续训练启动器按需创建，不提交模型、日志或临时文件。
默认只保留三份数据文件：

| 文件 | 保留方式 |
| --- | --- |
| resume.pt | 一份最新续训检查点，包含上述学习状态与限量回放；新文件校验成功后替换。 |
| best.pt | 一份最佳推理模型，只含 Actor/编码器权重、归一化和模型清单；内嵌同口径验证评分，达到选模条件后在保存事件中替换。 |
| metrics.jsonl | 一份限长摘要日志，起始上限 8 MiB；记录聚合损失、覆盖、路程、失败原因、验证结果与恢复事件。 |

不额外复制 last、final、每轮模型或每个随机种子的模型目录；best.pt 不重复保存双 Q、优化器与经验。
模型清单和必要配置内嵌文件，不另导出一套配置副本。切换训练种子时按实验计划复用目录，
只累积小型最终指标，自动重启则必须恢复原种子训练进度，不能静默切换实验。
best.pt 在当前种子内选优，完成该种子最佳模型的测试后才进入下一种子。
下一独立种子重新初始化网络、优化器、回放和选模评分，并覆盖前一种子的模型文件；
不继承前一种子的训练权重后仍报告为独立训练，也不额外累计一套跨种子最佳模型。
恢复时先核对 best.pt 与当前实验、种子的标识一致，再以其自身评分和训练步为准，
避免它比最近 resume.pt 更新时丢失选模记录，也避免沿用前一种子的评分。

依据第 4.6 节资源预算，将整个训练产物目录限制为 20480 MiB，检查点回放部分限制为 2048 MiB，
输出所在文件系统保留至少 20480 MiB 可用空间；这些是可配置预算，不是已测出的文件大小。
目前 /home 的余量允许该预算；可用空间足够时也不增加模型保留份数或原始数据记录。
总预算包含日志、模型、必要的小型控制文件和写入中的临时副本，也覆盖多个种子的累计产物。
若后续启用第 4.2.4 节外部地图，必要裁剪和下载/转换暂存也占用同一预算；默认不创建资产目录。
保存前按实际张量、回放依赖和序列化开销估算，写入时限制字节数；不能假设某个压缩比必然成立。
序列化只选定需要保存的不可变数据，采用受限缓冲，不另复制整份 8～12 GiB 内存经验池；
保存时固定引用的数据、模型快照和缓冲都计入总主存预算。
预算不足先减少回放片段并释放其独占依赖，不删优化器冒充完整续训。
连核心学习状态及安全替换峰值都容不下时，保留旧检查点，暂停并报告最低所需容量。

同一目录只允许一个写入者，检查点、最佳模型与日志压缩依次更新。安全替换流程为：

~~~text
检查总配额、可用空间与本次写入峰值
→ 同目录写临时文件（旧文件仍保留）
→ flush/fsync，校验可读性、载荷及回放引用完整性
→ os.replace 原子替换目标文件，再同步目录
→ 清理本写入流程的临时文件
~~~

同目录替换避免跨文件系统重命名；成功的 os.replace 在 POSIX 上具有原子性。[R9]
写满、校验失败或替换前崩溃均不先删除旧检查点。恢复时在独占目录后处理本流程遗留的确切临时文件，
不扫描删除其他目录或其他任务产物。只保留一份完整检查点意味着没有额外历史副本用于恢复介质损坏。

日志按训练批次间隔聚合，较旧明细合并或淘汰，保留当前实验配置标识与验证/测试摘要；
覆盖—路程曲线按固定数量的区间采样，不保存无限增长的逐控制周期轨迹。
隔离训练启动器应关闭 ROS 默认文件日志及 launch 按时间新建日志目录的行为，
必要的状态和故障摘要接入上述限长日志，避免 ~/.ros/log 在预算外持续增长。
默认关闭 rosbag、视频、截图、逐步地图、神经特征、独立教师数据集、TensorBoard 事件与 profiler trace。
场景由种子和生成器版本重建，不常规导出真值地图；这不替代经验中必须保留的历史可见观测。
需要部署时再导出一种目标模型格式，并纳入同一预算；不在每次保存时同时导出多种格式。

## 12. 推理与现有项目接入

### 12.1 决策接口

建议将探索器的“目标来源”从传统候选结构中解耦，增加互斥的 frontier / rl 策略模式。
两种模式共享任务输入、导航 Action 适配、结果统计及覆盖监视；
rl 模式直接接收连续目标，不走候选排名、前沿抑制和“无前沿即完成”的旧分支。
实现时需评估抽取共享执行层或新增薄节点的改动范围，保持唯一活动目标所有者。

复用的既有接口包括：

| 功能 | 既有接口 |
| --- | --- |
| 任务输入 | lunar_pure_exploration_msgs/msg/PureExplorationTask，包含任务角点及 START/PAUSE/RESUME/CANCEL。 |
| 地图原始输入 | grid_map_msgs/msg/GridMap，只有地图所有者订阅。 |
| 位姿 | nav_msgs/msg/Odometry 和直接 map→odom TF。 |
| 连续目标 | lunar_planning_msgs/action/NavigateToPose。 |
| 规划参考 | lunar_planning_msgs/msg/PathReference。 |
| 路径跟踪 | nav_msgs/msg/Path，现有控制器消费。 |

策略地图、有效观测统计、处理确认和 epoch/reset 是需要新增或补足的派生接口。
不能将调试窗口、量化后的可视化 cost 或只有 coarse 三值状态的图当作完整策略输入。
缓存的是这些派生结果，地图的累计与物理判定仍只有一个所有者。

### 12.2 推理流程

1. 收到合法任务，冻结任务统计格几何、预处理版本、动作尺度和模型配置。
2. 等待有效地图与平台位姿，初始化本任务观测账本和 GRU 状态。
3. 从一致快照构造全局 tile、局部视图和附加状态。
4. Actor 输出连续动作，解码后交给 NavigateToPose。
5. 沿途继续地图更新和覆盖监视；当前目标结束后更新执行历史并进入下一决策。
6. 覆盖达标、估计耗尽、取消或故障时按第 9 节明确结束类型。

推理阶段只加载 Actor、感知编码器、归一化与循环状态，不需要训练用双 Q、经验池和优化器。
训练与推理共用坐标变换、观测通道顺序、缺失值处理和动作解码代码。
首版以可验证的 PyTorch 推理为基线；如 Orin 资源实测需要，再评估 ONNX 等导出，
对动态 tile 数量、attention mask 和 GRU 状态做数值一致性验证。

模型清单至少包含地图分辨率、局部窗口边长与裁剪规则、通道语义、坐标与动作尺度、传感器配置范围、平台配置、
metric_version、训练代码提交和模型校验值。
加载时读取导航器实际窗口配置与 fine 分辨率，核对模型支持范围；
配置不匹配时明确拒绝加载或进入可解释的等待状态，不悄悄使用错误尺度。
推理循环状态在新任务初始化；best.pt 不携带某次训练回合的活动 GRU 状态。

传统策略可保留为显式可选模式。首版纯 RL 评估不使用后台前沿回退；
如部署需要回退，结果单列“混合策略”并报告启用次数，不能把混合表现作为纯 RL 性能。

## 13. 评估与验收

### 13.1 比较对象与公平性

至少包括现有前沿策略、相同任务接口下的连续 Recurrent SAC，
以及连续无循环 SAC 作为历史记忆消融。
资源允许时补充连续 PPO，对照算法也使用同样的导航器与实际执行路程。

所有对照共享场景种子、起点、初始地图、任务范围、传感器模型、平台参数、
覆盖统计与目标阈值。评估模型用确定性决策；随机策略基线需多次重复。

现有生产前沿输入默认是 1 m coarse 图，新策略同时利用 fine 视图。
因此需要分别报告“整个新系统相对当前系统的效果”和“相同地图信息条件下策略本身的效果”。
后者应给传统策略提供一致的派生信息，或设置相同输入条件的 RL 消融；
不能把增加精细地图的收益全部归因于强化学习。

传统算法因无前沿提前结束时，仍按统一覆盖监视器判断达标与否，
不把旧 COMPLETED 状态直接当成成功。

### 13.2 指标

| 指标 | 解释 |
| --- | --- |
| 覆盖目标达成率 | 达到配置覆盖目标的回合比例，注明原始/估计指标和评估收集预算。 |
| A_O、C_task、C_eff、A_X | 同时报告观测面积、原始覆盖、估计有效覆盖和排除量。 |
| C_ref | 仿真参考可观测集合上的覆盖，用来审计排除与假达标。 |
| 达到指定覆盖的实际路程 | 只比较达到相同阈值的结果；未达到者单独列出，不能按短路程获优。 |
| 覆盖—路程曲线 | C_task 或 C_ref 随实际路程变化，体现途中观测和回退收益。 |
| 导航目标有效率及失败分布 | 区分无效动作、NO_PATH、规划超时和输入故障。 |
| 碰撞与实际执行偏差 | 验证动作是否可执行、运动模型是否与导航配置一致。 |
| 估计误判达标率 | 在线报告达标但参考覆盖未达标的比例，附参考采样误差。 |
| 推理与闭环吞吐 | 推理延迟、有效高层转移/秒、地图派生/规划耗时和内存；时间是诊断指标。 |

任务没有固定截止时间，但有限实验必须公开采样资源上限。
未完成的截断回合不能报告为完整探索终局；既报告预算内达标率，也报告未完成覆盖与截断比例。
检查点按覆盖目标达成率、参考覆盖和误判情况优先筛选，再在可比覆盖下比较路程。
碰撞和接口错误作为独立约束，不用更高覆盖掩盖。

### 13.3 数据划分

按场景拓扑、布局和生成种子划分训练、验证、测试，不能把同一布局的不同起点当成完全独立泛化。
训练场景持续随机生成，验证与测试仅固定保存种子、生成器版本和起点等小型列表，不复制场景地图。
起始可用 20 个验证场景、40 个测试场景，每场景 3 个固定起点，覆盖月表和洞穴两类；
两类场景各自包含典型 100～300 m 与较大 300～1000 m 任务，按类型和尺度分组报告。
生成器版本及种子列表纳入检查点配置；修改生成规则后重新生成并版本化划分，不能悄悄改变验证集。
正式比较至少多个独立训练种子，建议 5 个，报告均值、离散程度及失败案例。
存储受限时依次完成训练与评估，在限长日志中保留各种子摘要，不默认长期保留每个种子的模型。
这些是实验设计规模，不是已经完成的数据集或训练结果。

### 13.4 必须覆盖的正确性场景

| 场景 | 验收要求 |
| --- | --- |
| 障碍首次被观测 | 增加 A_O，障碍后方不增加。 |
| 已有高程但通行判定仍 UNKNOWN | O 已知而 C 未定，覆盖不遗漏。 |
| footprint 膨胀到未观测格 | 不增加有效观测面积。 |
| 地图扩展、原点变化或重复发布 | 相同世界格不重复奖励。 |
| 仅排除量增大 | ΔA=0，覆盖奖励为零，并审计提前终止。 |
| 障碍环被发现有通道 | 撤回排除，剩余面积恢复。 |
| 任务外绕行再进入 | 导航允许，路程完整累计，覆盖只与 T 求交。 |
| 任务大于当前地图 | 未分配任务 tile 仍为未知并保留在分母和输入。 |
| 在已知通道长距离返回 | 不中途因零新增覆盖终止。 |
| 同位置改变 yaw | 由执行闭环转向，按真实新视野产生观测。 |
| 不可达连续目标 | 保留原始动作与失败，不吸附前沿后冒充成功。 |
| 目标失败前已经运动 | 运动和沿途收益都计入该步。 |
| 重复观测导致 revision 不增长 | 输入处理屏障仍能完成。 |
| reset 后旧消息到达 | epoch 隔离生效，不污染地图、路径和奖励。 |
| 回放旧地图 | 不能出现该时刻之后才观测的格。 |
| 局部窗口统一 | 64 m / 0.2 m 对应 320 × 320；边界裁剪与导航一致，较小窗口补齐不增加观测。 |
| 窗口配置变化 | 策略读取同一配置，模型不支持新尺寸或分辨率时明确报错，不继续用旧常量。 |
| 训练截断 | 使用 final observation 并正确 bootstrap。 |
| 正常中断后续训 | 网络、目标网络、优化器、α、课程与计数恢复；新 episode、地图和采集器循环状态正确重置。 |
| 限量回放恢复 | 所有历史 tile 引用可解析，序列可抽样；不足时先补采，不使用最新地图替代。 |
| 写入中断或磁盘不足 | 原检查点仍可读，无半文件替换；不把半条导航动作记录成成功转移。 |
| 缺失或损坏的检查点 | 明确恢复失败；不能用最佳推理权重冒充完整续训。 |
| 30 分钟周期保存 | 使用单调墙钟和 1800 s 间隔；正常退出/中断额外保存，无状态变化不重复写文件。 |
| 当前主机资源配置 | 正式训练与续训均固定 8 环境，batch=8、训练 CPU 8 线程；验证隔离、吞吐与资源峰值，不自动改变环境数。 |
| 总主存与经验池 | 8 GiB 目标、12 GiB 上限服从启动预算；含地图、回放依赖和保存暂存，不能同时按子项最大值占用。 |
| 项目内训练目录 | 项目根解析稳定；模型、日志与临时文件均被 Git 忽略，同一实验续训不另建时间戳目录。 |
| 多次保存与多种子运行 | 稳态文件不累积，总大小连同临时写入峰值不超过配置预算，ROS 日志无旁路增长。 |
| 资源过载或 DDS 故障 | 与策略失败分开报告，不能学到基础设施故障偏差。 |
| 多环境同时运行 | 地图、TF、任务、目标、控制器和统计互不串用。 |
| 程序生成地图 | 月表与洞穴均能按种子重建；不存在固定演示通道、全图预知或预填通行状态的捷径。 |
| 任务尺度与活动范围 | 覆盖 100～300 m 典型任务和约 1 km 任务；D 容纳外部绕行，不把边界算作已观测墙。 |
| 大地图接近全覆盖 | 保持 8 环境，测量累积 fine 地图、历史版本、回放和保存峰值；不足时明确报告，不能静默丢地图。 |
| 配置化模拟视野 | 初值 10 m、90°；修改量程/视角后观测、覆盖和环境侧参考面积一致，首个遮挡后方保持未知。 |
| 可选外部资源 | 默认不下载、不建资产目录；启用时裁剪、元信息和暂存纳入同一总配额。 |
