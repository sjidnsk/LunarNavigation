# 移动中滚动局部规划设计

状态：用户已确认对话方案；本文将该方案具体化，供书面评审。尚未实现。

基线：`integration/pure-planner-orin@6868236f`。
适用范围：`incremental_v2` 轮式导航与 `incremental_reference` 控制闭环。

## 目标与约束

车辆沿当前有效路径移动时持续更新局部路径，消除由“到达局部目标、停车、再规划”造成的非必要停顿。
保持架构合理、职责清楚、配置少；复用已有路径可行性和跟踪约束，不引入复杂的切换准入流程。
连续行驶不意味着急转、换向、障碍、定位不可用或最终到达时禁止停车。

不新增规划算法、控制器包、速度发布者、连接段规划器或多阶段路径交接协议；不修改探索策略、底盘协议及生产部署。
后续范围更新（用户要求）：足式 incremental_reference 平面执行模式复用相同候选计算、修订接续和运动约束，默认开启 0.5 s / 1 m 持续规划。要求跟踪反馈；可显式关闭。legacy 控制输入行为保持兼容。该范围不包含步态控制器或真实足式驱动适配。

## 已核查的问题

- `planning_session_coordinator.cpp`：正常执行时返回 `EXECUTING`，规划主要由初次规划、重规划或段结束触发。
- `incremental_navigation_node.cpp`：启用跟踪反馈时，段结束要求匹配当前 session/revision 的终态反馈和接近零的速度。
- `execution.py::set_path`：新路径进入 `BRAKING`，重置跟踪状态和无进展计时。
- `RunCycle` 同步调用 `PlanCycle`，搜索与活动引用更新耦合；若仅增加周期触发，会延迟同一调度链中的地图失效与事件处理。

因此，仅增加定时器或放宽到达判定不足以实现连续更新。
历史设计 `2026-09-04-incremental-wheeled-path-controller-design.md` 的纯 Path 输入描述不代表当前 reference 模式；
本设计沿用当前 `PathReference + TrackingStatus` 闭环，参考 `2026-09-10-incremental-controller-rviz.md` 的验证边界。

## 方案选择

采用周期滚动规划，以剩余路径距离触发提前更新。相比只在段末预计算，该方案能在移动中持续利用新地图；
相比增加连接轨迹和交接确认协议，该方案直接复用现有跟踪能力，改动范围更小。

## 职责与数据流

| 模块 | 职责 |
| --- | --- |
| 全局引导、局部目标选择 | 提供方向，根据请求起点选取前方局部目标，复用现有全局缓存 |
| 局部规划器 | 读取不可变地图与位姿输入，计算并返回候选路径及规划结果 |
| 规划协调器 | 管理任务、活动引用、触发策略、结果采用和任务终止 |
| ROS 节点 | 收发消息、捕获输入、运行单个计算工作线程、回传结果 |
| 控制器 | 根据实时位姿跟踪活动引用，负责限速、制动、对齐和执行反馈 |

数据流：最新地图/位姿 → 协调器创建计算请求 → 单个后台计算 → 协调器处理候选结果 → PathReference → 控制器。
计算期间，活动引用不变；控制反馈、取消、地图失效仍由协调器处理。
核心调度策略留在 core，ROS 适配层不决定路径优劣或车辆如何接续。

## 调度与并发

1. 首次规划沿用当前任务启动语义。获得活动路径后进入执行状态，后台计算忙闲作为独立内部字段，不增加组合业务状态。
2. 普通更新按 `rolling_replan_period_s` 调度；剩余弧长进入 `rolling_replan_distance_m` 时可提前触发一次。
3. 提前触发按活动引用去重；失败后按周期重试，不能因每个 tick 都处于距离阈值内而忙循环。
4. 同一时刻最多一个计算任务。忙碌时只合并一个待更新意图，不排队保存旧位姿；下一次调度重新捕获最新输入。
5. 普通地图或位姿更新不反复取消正在进行的搜索。任务取消、抢占、路径失效可中断搜索，并使相关旧结果失效。
6. 采用不可变请求/结果对象。协调器状态只有一个串行所有者；后台只使用请求快照及由工作线程独占的规划器缓存。
7. 销毁时请求停止并回收工作线程；不能让工作线程持有已销毁的节点或协调器。

主要调参只有更新周期和提前距离。周期设为 0 表示关闭滚动更新，恢复段结束调度；拒绝负值和非有限值。
首轮隔离实验启用正周期；生产配置沿用关闭状态，直到对应环境验证和部署授权。
周期、提前距离的启用值依据测得的规划耗时、车速和制动距离记录在验证报告中，不在设计阶段宣称最优频率。
提前距离应覆盖计算期间行程与制动余量；如果局部路径过短或计算过慢，允许在路径末端停车，不越过有效路径。

## 候选计算与结果采用

将现有同步周期拆为请求准备、候选计算、结果应用三部分；具体 API 在实施计划中映射，避免为了异步复制一套规划逻辑。
请求携带任务身份、内部请求代号、起点和地图快照。内部代号不扩展 ROS 消息。

- 结果属于已取消、已结束或被抢占任务，或已被失效事件淘汰：丢弃。
- 无解、超时、没有局部进展：作为本次更新失败；活动路径仍可执行时保留它并按周期再试。
- 没有可执行路径：沿用当前等待地图、重规划及终止分类，不无限吞掉失败。
- 成功：由协调器分配新的 `segment_revision`，发布新的 ACTIVE 引用，不先清空旧路径、不等待停车确认。
- 相同路径且最终目标语义不变：可不发布重复引用；不得要求新路径比旧路径“明显更优”才允许更新。

地图修订号变化本身不是拒绝条件。若计算期间地图改变，复用规划层的路径可行性检查检查候选剩余部分；
不能仅改写 revision 就声称已经检查，也不能把当前“未发现 blocked”的检查扩大解释为完整路径认证。
实现时保留既有平台可行性、起点补丁和未知区域语义，不增设独立安全评分层。
地图检查不下沉到控制器；控制器也不因地图版本变化自行否决引用。

活动路径失效时，立即发布对应 INVALIDATED，保留现有停止执行语义。后台正常更新不得阻塞此处理。
旧引用的 COMPLETED/FAILED 反馈不能终止或改写新引用；使用已有 session/revision 匹配规则。

## 控制器更新语义

首次引用、新任务、已经失败或正在处理失效的执行器，沿用原启动/恢复流程。
同一任务正常 TRACKING 中收到新引用时：

1. 使用实时位姿投影到新路径前向可跟踪部分，重建索引、弧长进度、转角停止点。
2. 不把旧路径的弧长数值用于新路径；不默认回到路径起点，不强制进入 BRAKING。
3. 保留实际速度驱动的加减速约束。新路径方向、曲率或误差超过既有能力时，仍由原控制逻辑制动、对齐或报告偏离。
4. 换向必须完成现有制动过程，不能只改变 direction 符号实现热切换。
5. 路径更新不清空任务级无进展计时。使用实际位姿运动积累平移进展证据；对齐进展仍按实际角度变化统计。
   不跨路径比较弧长，不把收到新版本当成“已前进”。

投影是定位跟踪进度，不生成一条从车辆位置直连路径的可执行捷径。
起点已落后、车辆偏离过大或方向突变时由既有跟踪限制处理；不增加连接段搜索或预测轨迹同步机制。
自交路径应按有序路径前向连续性选取投影，避免简单全局最近点跳到后续分支。

## 局部末端与最终目标

- 非最终局部段只承担接续：下一引用可用时继续跟踪，不要求达到旧局部目标。
- 未获得下一引用时仍在已知路径末端减速停止，但非最终末端不进行最终 yaw 对齐。
- 对最终引用进入 FINAL_ALIGN 时冻结普通刷新，并淘汰尚未应用的普通更新结果，防止打断收尾。
- 冻结期间仍处理地图失效、取消和执行失败。需要恢复重规划时解除冻结。
- 最终成功继续要求当前 session/revision 的执行确认、目标位置和必要朝向满足要求并停稳。
  不能因周期规划、旧段完成或仅位置接近而直接报告 GOAL_REACHED。

## 接口与修改范围

保持 NavigateToPose、PathReference、TrackingStatus 的消息定义、topic 和唯一速度发布者边界。
候选路径是内部计算结果，不引入第二条执行路径 topic，不增加接收确认服务。

预期修改：core 协调器及单周期计算边界、ROS 导航节点调度、轮式 execution/reference 适配、相关参数/launch 和测试。
复用现有规划器、路径解析、控制限幅和地图检查，避免无关重构。

## 验收与证据

| 场景 | 必须观察到的行为 |
| --- | --- |
| 平顺多段行驶 | 旧局部终点到达前更新引用；更新本身不产生 BRAKING/ALIGNING 停顿 |
| 慢计算、连续输入 | 最多一个计算，无请求积压；控制和取消/失效处理保持响应 |
| 一次更新无解或超时 | 旧路径仍有效时继续执行，任务不被立即终止 |
| 计算期间障碍改变路径 | 活动路径及时失效；失效前的后台结果不能使其复活 |
| 新路径起点落后、自交或偏离 | 无回头追起点、无错误跨分支跳进度、无越过跟踪限制 |
| 急转和换向 | 保留所需制动、对齐，加减速与曲率限制不退化 |
| 持续更新但车体卡住 | 无进展监测仍触发，不能靠新版本无限续命 |
| 最终对齐、取消、抢占 | 终态正确且只提交一次，旧结果和旧反馈不能覆盖当前状态 |
| 滚动关闭和其他输入模式 | 原有段结束行为及兼容模式回归通过 |
