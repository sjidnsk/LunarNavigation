# 全局路线与终点优化方案草案

## 目标及边界

路径更短、终点连接顺畅、降低重复几何计算；保留现有全局/局部/执行职责，不新增任务实体、ROS消息、停滞累计或超时门禁。主线owner，当前P4运行暂不切换。用户已明确终点朝向容差5度，该独立子批先提交。

## 推荐分批方案A：保留分解，按通道边界拉直

1. 全局分解/搜索保留，重建所选自由通道的完整portal边界，而不是只保留中点；在通道内执行漏斗拉直。仅在同净空、连续碰撞验证通过且长度不变长时接收，再做已有拐角平滑。它改善选中通道内的路径，不承诺跨不同绕障通道的严格全局最短。
2. 已有整形模块增加可选终点几何连接：用最终yaw对应的前进/倒车相容切线构造有界末段Bezier，复用连续几何证明。空间不足则保留可行原路，剩余姿态原地完成。全局只给几何曲线，不输出速度，不替局部MPCC决定运动可行性或实际方向。
3. 先剖析构图、搜索、拉直、曲线细分、当前图复核耗时；复用现有几何工具和同图证据，加入精确包围盒筛选减少不相关障碍计算。保留总预算和碰撞语义，不引入与当前分支分离的缓存实验。
4. 完成判定按5度、10厘米及既有实测停稳标准审查。捕获实测/预测边界不一致、P3低频、多帧抖动及目标替换案例，排除重复几何判定；不把单个历史停稳观测或预测到达直接冒充当前完成，不增加新计时器。

## 备选方案B：同时替换全局搜索

若要求在当前膨胀障碍几何下尽量保证跨绕行通道的欧氏最短，而不仅删掉当前路线明显冗余，则需要基于障碍可见性/区间的搜索。先用小场景精确参考解比较，再评估障碍顶点数量、相交处理和最坏时间；不能把全连接图强塞进现有实时预算。末段朝向曲线依然可能比纯位置最短线略长。

## 验证与决策

推荐先A，范围和成本更可控；若用户选择B，须先验证搜索规模与性能预算，不能声称A已经做到严格全局最短。每批先回归捕获反例，再改原有模块，独立复审后分别提交；ROS变化需隔离Humble构建/测试，运行部署另按当前会话授权安排，不自动merge/push。

标准通道/直线路径分离可参考Detour findStraightPath：https://github.com/recastnavigation/recastnavigation/blob/main/Detour/Source/DetourNavMeshQuery.cpp 。仅参考职责和算法思路，不引入整个库。

当前草案待用户选择范围及确认；生产算法尚未修改。
