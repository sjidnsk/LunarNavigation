# P3定位失效停车等待与自动恢复

用户已选择自动恢复；沿现有Python/ROS2架构，单线程主写入。这是导航、跟踪、反馈合同的耦合切片，不拆分独立实现者。

设计：导航owner独立检查真实定位源龄/接收龄，失效时保留任务目标、使旧规划缓存失效、进入现有PLANNING等待。跟踪器缺定位持续零速请求，报告当前严格配对参考的WAITING且accepted=false，不把输入故障伪造成参考接受或停稳。新鲜等待心跳保持任务；控制器真正失联仍触发现有反馈超时。定位连续有效2秒并有源戳推进后重新规划，跟踪器需新参考、真实停稳与完整停车认证才能恢复，旧运动不得复活。暂不改P3输出、不扩大原输入预算、不新增消息或任务身份。

- [x] 先失败回归：定位丢失不终结任务、等待不算到达、缺心跳仍失败、旧故障不被恢复吞掉。
- [x] 输入有效性/等待/源推进和状态失效实现；统一planner/follower消费同一定位预算，保持其他模块职责。
- [x] 跟踪零速等待、禁止旧参考复活、真实停稳及新参考认证后接管；取消/换目标保持。
- [x] 隔离测试及目标包构建；合入主线并同步TCP/P4，重启无控制导航探索，记录实际输入及未通过闭环。
